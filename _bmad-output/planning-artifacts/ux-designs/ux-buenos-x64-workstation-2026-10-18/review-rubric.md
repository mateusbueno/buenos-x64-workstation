# Spine Pair Review — Ladiani Velora 73

## Overall verdict
The pair is a strong contract for the core stage experience (Performance, pickup, seamless switching, panel ↔ screen mapping, Write guard). Every `{token}` reference resolves, the component tables match 35-for-35 across both spines, and the section shape is canonical. It is thin away from that core. CAP-19 (arpeggiator) has no UX at all. Building a set on the device is a stated Foundation premise, yet it has no flow, and its surfaces (Part, Effects, Scenes) are undesigned. Failure states for import, firmware update and Velora Studio transfer/write are missing. One critical color gap: drawbar heads have no light-theme values, and white heads disappear (1.02:1) in the Studio theme.

## 1. Flow coverage — thin
Checked: sources resolve to SPEC.md (CAP-1..CAP-19, no UJs), the architecture spine, HARDWARE-INTERFACES and .memlog. UX-facing CAPs (4, 7, 8, 10, 12, 13, 14, 15, 16, 17, 18, 19), plus the memlog journeys (stage night, prepare sets on the keyboard, studio import/refine), were mapped to Key Flows. The three flows each have a named protagonist, numbered steps, a bold climax and failure paths. Covered: CAP-4 (Flow 1 step 5), CAP-8 (Flow 2), CAP-15 (Flow 3), CAP-16 (Flow 1 step 1), CAP-17 (Flow 2 failure).
### Findings
- **high** CAP-19 (arpeggiator on any part, internal tempo or external MIDI clock) does not appear anywhere in either spine. There is no control, surface, state or flow. The Top Bar shows "♩ 72" with no clock-source treatment (EXPERIENCE.md all sections; DESIGN.md Top Bar). *Fix:* place arp on/off and settings in the Part surface and in the Studio Part Editor. Define the tempo/clock-source display (internal vs DIN/USB clock, clock lost). Add a short flow or Flow 1 beat.
- **high** Foundation says "Players build sets on the device itself", and the memlog records this as a journey decision. No Key Flow creates a Live Set, assigns 8 timbres, sets splits/layers (CAP-7), creates scenes or edits effects (CAP-13) on the device. The Part, Effects and Scenes surfaces are "spine-only" with no content (EXPERIENCE.md Foundation, IA, Open Questions; DESIGN.md Open Questions). Zone editing is shown only in Studio (Flow 2 step 6). *Fix:* add Flow 4, "Preparing a Live Set on the keyboard" (new Live Set → parts → split → scenes → Write), and commit the content and layout of Part, Effects and Scenes, at least as a structure table each.
- **high** Flow 3's climax claims "found, heard and placed within three interactions", but the steps count four: tap timbre name, tap Strings chip, turn VALUE to highlight, WRITE. Scrolling a category in a 1,000+ instrument library (CAP-15 success) is not addressed (EXPERIENCE.md Flow 3 steps 1–4). *Fix:* define what counts as one interaction. Show the path that meets CAP-15 (e.g. search to a unique hit, or chip + first-page result), or state the gap upstream.
- **medium** CAP-14 desktop path (Studio transfers and activates a library over the mediated USB protocol) has no flow. Flow 2 only uses USB-A import on the device, and Studio "Library management" is one IA row (EXPERIENCE.md IA › Velora Studio surfaces). *Fix:* add steps to Flow 2 or a separate flow: choose library in Studio → convert → transfer progress → activated on device.
- **medium** CAP-12 / CAP-17 firmware update has no flow (Settings › System & Update and Studio Sidebar › DEVICE › firmware are named only) (EXPERIENCE.md IA). *Fix:* add a short update flow with the power-loss failure path (boots previous or new firmware).
- **medium** CAP-18: velocity curves and aftertouch have no settings surface. Settings › Keyboard & Pedals lists only the footswitch function (EXPERIENCE.md IA Settings row). *Fix:* list velocity curve (and aftertouch when present) under Keyboard & Pedals.
- **low** CAP-10 (USB-C audio/MIDI interface) shows only as Settings › Computer, with no state for "USB audio active" (EXPERIENCE.md IA). *Fix:* state whether the Status Bar indicates a USB host connection.

## 2. Token completeness — thin
Checked: 66 prose/component references in DESIGN.md and 7 in EXPERIENCE.md all resolve. All colors are hex, with Stage/Studio pairs for the semantic set. Contrast ratios were recomputed (WCAG 2.x) and the stated values are correct for the listed pairs. Typography gives px at the native panel. Wordmark and panel-legend sizes are notes deferred to designers (acceptable).
### Findings
- **critical** Drawbar head colors have no light-theme pairs (`drawbar-brown/white/black` and their inks exist once). The device's Studio theme is user-selectable and renders DRAWBARS mode on `surface-light`, so `drawbar-white` `#e7e4dc` on `surface-light` `#e3e8e4` = **1.02:1**, which is invisible. It is listed only as an Open Question (DESIGN.md frontmatter `colors`; Open Questions "Drawbar heads in the Studio (light) theme"). *Fix:* add `drawbar-*-light` tokens (or a `drawbar-white-edge` for light) with contrast against `surface-light` stated, and reference them from `components.drawbar-column`.
- **high** Off parts render at `off-opacity: 0.42`. Measured, the timbre name is 3.58:1 (Stage) / 2.61:1 (Studio), and the muted category is ~2.0 / 1.7:1. That contradicts the stated floor "Every text pair is ≥ 4.5:1" and the Do's row (DESIGN.md `components.part-strip.off-opacity`; Colors "Contrast floor"; Accessibility Floor "Never color-only"). *Fix:* replace opacity with explicit off-state tokens (e.g. `text-off-dark/light` ≥ 4.5:1, or dim only LED/Volume Bar), or explicitly exempt disabled text and say why.
- **medium** "Large text on Performance" is a shipping Settings option with no tokens (DESIGN.md Typography last bullet, Open Questions; EXPERIENCE.md IA Settings, Accessibility Floor). *Fix:* add `*-large` typography tokens for the Performance roles, or a scale factor, and check the 1024×600 layout still fits.
- **medium** Panel legend contrast is quoted only against `alu-mid` (4.74). Against the gradient's dark stop `alu-low` it is 3.9:1, below the 4.5 floor the Do's table asserts (DESIGN.md Colors "Measured contrast"). *Fix:* quote against the darkest stop and darken `panel-legend`, or mark panel values as render-only and exempt.
- **low** The `● Ready` indicator token is `{colors.accent-dark}` (DESIGN.md `components.live-set-hero.ready-indicator`, Live Set Hero row), while EXPERIENCE.md State Patterns says `{colors.ok-dark}`. Same hex today, divergent role. *Fix:* point the component token to `ok`.
- **low** Unreferenced tokens: `drawbar-*-ink`, `alu-mid`, `typography.organ-name`, `spacing.1`, `spacing.4`. The Studio theme relies on an implicit "swap each -dark for its -light twin" rule, which breaks for tokens without twins (DESIGN.md frontmatter; Components intro). *Fix:* reference the inks and `organ-name` from `drawbar-column` / `organ-card`. List the tokens that have no twin and are theme-invariant.
- **low** Notice Toast is called a "pill" but tokenized `{rounded.md}`. Shapes reserves `{rounded.full}` for pills (DESIGN.md Components Notice Toast; `components.notice-toast.radius`; Shapes). *Fix:* align one way.
- **low** Empty-slot dashed outline `line` vs `surface` = 1.35:1 (Stage) / 1.22:1 (Studio), below the 3:1 non-text guidance. The muted number carries the meaning (DESIGN.md Scene Tile, Shapes). *Fix:* use `muted` for the dashed stroke, or state the exemption.

## 3. Component coverage — adequate
Checked: 35 components named in DESIGN.md Components, and the same 35 names in EXPERIENCE.md Component Patterns, all with real rules. Then every component-like noun in IA, State Patterns, Flows and Layout.
### Findings
- **medium** The on-screen keyboard is used by Search Field, the Write Dialog name field and Flow 3, but has no visual or behavioral spec (layout, PT-BR/ES diacritics, VALUE interaction, dismissal, what it covers on 1024×600) (EXPERIENCE.md Search Field row, Flow 3 step 2; DESIGN.md Write Dialog). *Fix:* add an "On-screen Keyboard" row to both spines.
- **medium** The 17-category picker opened by Category Chip has no component row (EXPERIENCE.md Category Chip, Flow 2 step 3). *Fix:* add "Category Picker" (grid/list, localized labels, apply-to-all) to both spines.
- **medium** Velora Studio pieces are named but not specced: the footer status line ("UNSAVED: SCENE 2", "LIVE EDIT ON", last backup), the Live Set header and scene tiles, and the Merge/Replace restore dialog. The device-side container for "Replace timbre / Import" on a missing library is also undefined (DESIGN.md Layout Velora Studio, Unsaved Indicator; EXPERIENCE.md State Patterns Unsaved/Live edit/Restore/Missing library). *Fix:* add rows (Studio Footer, Studio Scene Tile or "reuses Scene Tile", Studio Dialog, Action Sheet) or state reuse.
- **low** Physical navigation controls (LIVE SET ◀ ▶, SCENE ◀ ▶, EXIT, WRITE, VALUE encoder, ROTARY STOP/S·F, wheels, footswitch, MASTER) have no rows. MENU Button refers to "the other navigation buttons". Settings on/off options (reduced motion, large text) have no named control (DESIGN.md MENU Button; EXPERIENCE.md Interaction Primitives). *Fix:* add one "Navigation Button" row and name the Settings toggle control (Segmented Control or a switch).

## 4. State coverage — thin
Checked: every IA surface (11 device, 5 Studio) for empty, loading, focus, error, offline and permission states. Performance is well covered: pickup, ready, loading, missing library, no organ, two organs, unsaved, empty, USB toast. Studio covers offline, connected, live edit and restore. Part, Effects, Scenes and Launcher have no states (see §1).
### Findings
- **high** Import has no failure states: insufficient storage (Flow 2 is 18.4 GB, CAP-14 is 300 GB), drive removed mid-import, unsupported/corrupt file or opcodes outside the v1 subset (CAP-8), already-imported duplicate (EXPERIENCE.md State Patterns, Import rows). *Fix:* add rows with copy and recovery for each, in the same voice as "Missing library".
- **high** Firmware update states are absent on device and Studio: in progress, cannot play during update?, success, failure, booted into previous firmware after power loss (CAP-12, CAP-17) (EXPERIENCE.md State Patterns; IA Settings › System & Update, Studio Device). *Fix:* add update states, including whether sound is available during download vs install.
- **high** Velora Studio is missing: library transfer progress/failure (CAP-14), "Write to Velora" in progress/failed, first-time pairing (the title bar says "PAIRED" but pairing is never defined), app ↔ firmware version mismatch. Disconnect mid-edit is left as an Open Question (EXPERIENCE.md State Patterns Studio rows, Open Questions). *Fix:* add these rows. Resolve disconnect-mid-edit (e.g. edits stay on device unsaved with `●`).
- **medium** Performance gaps: end of setlist (what NEXT shows on the last song), a Live Set played with no setlist loaded (Top Bar context), device indication while Velora Studio is live-editing, tempo when following external clock or clock lost (EXPERIENCE.md State Patterns; DESIGN.md Top Bar, Live Set Hero). *Fix:* add rows.
- **medium** Focus/highlight is not a state pattern. VALUE-driven highlight is mentioned per component (Launcher, Result Tile) but has no shared treatment, and Studio keyboard focus is undefined (EXPERIENCE.md State Patterns, Accessibility Floor). *Fix:* add a "Highlighted / focused" row for device (raised + accent edge) and for Studio (focus ring token).
- **medium** Empty states are missing for first run (no setlists), empty ★ Favorites / Recent chips in Library and Setlist Browser (EXPERIENCE.md State Patterns). *Fix:* add copy per surface.
- **medium** Write edge cases: unsaved edits pending on several Live Sets (the indicator only shows on the current one, and the dialog scopes only to it); choosing scope "Scene" when the edit is Live Set-level (Flow 3 changes a part's timbre); Save-as-new name collision; storage full (EXPERIENCE.md Unsaved Indicator, Write Dialog, State Patterns Unsaved changes). *Fix:* define which scopes are offered per edit type and how other Live Sets' pending edits surface.
- **low** Boot covers only "restore last sound". The "Boot into" alternatives (start of setlist, default Live Set), a restore target with a missing library, and boot failure are not covered (EXPERIENCE.md IA Boot, State Patterns Restoring). *Fix:* add rows.

DESIGN.md Components rows (Write Dialog, Import Row, Result Tile, Boot Screen…) have no inline links, while EXPERIENCE.md IA uses §1–§6 (DESIGN.md Layout & Spacing, Components). *Fix:* add §-anchored links on the relevant rows.
- **low** Unmocked surfaces and themes (Launcher, Notice Toast, ASSIGN Overlay, Part/Effects/Scenes, Studio light theme, drawbars light) are acknowledged as spine-only. This is acceptable, but the drawbar-light and Launcher gaps carry the §1/§2 findings.

## 6. Bloat & overspecification — adequate
### Findings
- **medium** The same facts are restated in many places, which risks drift. The 7-tile Launcher list appears in 5 places (DESIGN.md Layout, DESIGN.md Components, EXPERIENCE.md IA, Component Patterns, Interaction Primitives › Navigation), and the memlog shows it already drifted once (Part → Setlist). The ASSIGN "3 s" appears in 5 places, the Performance touch shortcuts in 3 (IA, Component Patterns, IP table), and the 500 ms long press in about 6. *Fix:* give each fact one home (IP for timings and shortcuts, IA for the Launcher list) and reference it elsewhere.
- **low** EXPERIENCE.md Localization duplicates Foundation › Languages, and "Assign & Global Defaults" largely duplicates the ASSIGN Overlay row and IP › ASSIGN feedback. *Fix:* fold each into one section.
- **low** DESIGN.md Colors carries derivation history (old → new hex for muted/warn), which is memlog material. EXPERIENCE.md Inspiration "Lifted from Ferrari: exclusivity" and "Lifted from Apple" are brand posture with no behavioral decision attached, so they belong in DESIGN.md Brand & Style (which already says it). *Fix:* trim.

## 7. Inheritance discipline — adequate
Checked: all `sources` paths resolve. CAP citations (CAP-8, 14, 15, 16, 17) match spec meaning. AD-20/23/24 exist in the architecture spine. EXPERIENCE token references resolve. Component names are identical across all sections of both files.
### Findings
- **high** WRITE and EXIT semantics conflict across sections. Flow 1's failure path says "A brief press of WRITE does nothing (guard)", yet a short WRITE loads a setlist (Flow 1 step 2), assigns a timbre (Flow 3 step 4; Result Tile), opens a Launcher tile and starts an import (Flow 2 step 3). EXIT "goes back / cancels (to Performance)" (IP › Navigation), but from Library reached via the Part surface, is "back" Part or Performance? Launcher: "EXIT returns to Performance, MENU again closes" (closes to where?) (EXPERIENCE.md Interaction Primitives, Component Patterns Launcher Grid / Write Dialog, Flows 1–3). *Fix:* add one rule table in Interaction Primitives. WRITE short = confirm on non-Performance surfaces / no-op on Performance. WRITE hold 0.5 s = Write Dialog, on which surfaces. EXIT = one level back vs straight to Performance. MENU-again = return to the previous surface.
- **medium** Glossary collisions with sources. The spec uses "performance" (CAP-7) and "default program" (CAP-16), the architecture uses "programs and performances" and "performance state", and the spec glossary uses "Companion app". The spines use Live Set and Velora Studio, and also name the home surface "Performance" while banning "performance" as a UI synonym. This is flagged upstream (#11), but there is no mapping for consumers now (EXPERIENCE.md Voice and Tone, Upstream Feedback 11; SPEC.md CAP-7/16; glossary.md). *Fix:* add a term-mapping table to Foundation (Live Set = spec performance/program; Velora Studio = Companion app; Performance surface ≠ architecture performance state).
- **low** Vocabulary drift inside the spines. Import copy uses "instrument(s)" ("7 instruments", "1 instrument needs a category"), while the fixed vocabulary is Timbre. State Patterns hard-code `{colors.warn-dark}` / `{colors.ok-dark}` where the theme-swapped role is meant (EXPERIENCE.md State Patterns, Flow 2; Voice and Tone). *Fix:* pick Timbre (or define "instrument" as the imported library unit). Reference roles (`warn`, `ok`) with the swap rule.

## 8. Shape fit — strong
DESIGN.md sections are in canonical order (Brand & Style → Colors → Typography → Layout & Spacing → Elevation & Depth → Shapes → Components → Do's and Don'ts), followed by Open Questions and Deferred, both of which earn their place as handoff. EXPERIENCE.md has all required defaults. Inspiration is present (memlog references Nord/Apple/Ferrari and rejects Motif XS). Responsive & Platform is present (two surfaces). Invented sections earn their place: Seamless Switching (hard requirement), Panel ↔ Screen Mapping, Categories (data table), Upstream Feedback. Localization and Assign & Global Defaults are the weakest (see §6).
