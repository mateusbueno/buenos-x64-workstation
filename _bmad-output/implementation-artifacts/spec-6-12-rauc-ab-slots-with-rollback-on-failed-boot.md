## Intent

**Problem:** Firmware cannot be updated safely: there are no A/B install slots, no signed update bundle and no rollback when a new slot fails to boot (FR66, AR36 partial, AR2 partial).

**Approach:** Extend the `yocto/` layer with meta-rauc (Wrynose branch, RAUC >= 1.15.2; check with `git ls-remote` that it exists and pin it, else report the gap and do not invent) and: a RAUC system config declaring slots `rootfs.0`/`rootfs.1` (matching the `rootfs.0`/`rootfs.1` GPT names of the Story 6.11 wks) with a U-Boot bootloader backend as the placeholder for the chain chosen in Story 1.6 (not done yet; mark `TODO(Story 1.6)`), a bundle recipe producing a bundle signed with the dev root, the dev image carrying only the dev keyring, a systemd "mark good" unit that runs only after engine, ui and sysd are ready (services do not exist yet: define the targets/ready-conditions contract and a placeholder dependency set, `TODO` markers), a rollback record written by `sysd` to a small state file under `/data/config` (implement the writer as a small, testable script/tool plus its unit now, since sysd does not exist), and Docker tests proving what can be proven without a boot: `rauc` builds a signed bundle, `rauc info` verifies it with the dev keyring, a bundle signed with a key outside the dev keyring is rejected, a bundle with one flipped byte is rejected, all before any slot would be written.

## Boundaries & Constraints

**Always:** Dev signing material is generated by a script into a directory OUTSIDE the repository (per KEY-HIERARCHY.md "RAUC bundle signing | dev"), never committed; the committed repo holds no private key and tools/ci/check_no_private_keys.py must stay green (only add allowlist entries for a public certificate after reasoning, with a comment). The Docker test generates throwaway dev and "foreign" roots in a temp dir inside the container at run time. The dev image carries ONLY the dev keyring (public cert) — the keyring is supplied by path variable (e.g. RAUC_KEYRING_FILE) with a recipe-level fatal check when missing, so the layer parses without keys; the validation supplies the throwaway cert. Slot names and device paths use PARTLABEL naming consistent with the wks; the boot-attempt counter is 3 attempts (bootloader backend config, U-Boot env variables BOOT_ORDER/BOOT_x_LEFT as the standard RAUC U-Boot contract: provide the boot script/env snippet as a committed file and test its logic if feasible by running the script's decision logic in a shell/U-Boot-free simulation or by documenting it clearly). Mark-good unit orders After= the three service targets and uses `rauc status mark-good`; it must NOT be wanted by default.target before those are active (state the contract). The rollback record (from-version, to-version, timestamp, reason) is written atomically (temp + fsync + rename) to `/data/config/rollback.json`; test the writer in Docker with a sample RAUC status input.

**Never:** No real install, boot or rollback (dev board), no production/factory-test keys or keyrings (Story 6.13), no full image build (disk), no changes outside `yocto/`, docs and CI workflow. Do not fabricate upstream layer URLs or versions.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Valid bundle | bundle signed by dev root | `rauc info` verifies against dev keyring | none |
| Foreign key | signed by a key outside the keyring | rejected, no slot would be written | test asserts rejection |
| Tampered | one byte flipped | rejected | test asserts rejection |
| System config | rauc system.conf | slots rootfs.0/rootfs.1, u-boot backend, bundle verification keyring path | static + rauc check |
| Mark good | services ready | slot marked good only after engine, ui, sysd ready | unit ordering checked |
| Rollback record | RAUC status shows booted slot != attempted slot | rollback.json written atomically with from/to version | write failure leaves previous file |
| Missing keyring | layer built without keyring variable | clear bbfatal at image build; layer parse unaffected | none |
