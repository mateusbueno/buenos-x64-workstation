## Intent

**Problem:** "Imports and plays with mapping intact" had only been shown on a synthetic library and on an env-gated demo test that had never met a real library (FR20, NFR19, AR2 partial, EXT5 dependency).

**Approach:** One tool, `tools/corpus/`, reuses the existing importer (`librarian import`), renderer (`velora-offline-render --engine sample`), harness (`velora-null-test` with the Story 1.15 settings) and oracle (`tools/oracle/render-oracle.sh`, sfizz 1.2.3); there is no second importer or oracle. It adds a pinned manifest, a fetch with cache and hash verification and hardened extraction, a generated six-probe MIDI suite, a runner that fails on any import or null-test failure, a report, offline unit tests and a manual-only workflow definition.

## Boundaries & Constraints

**Always:** audio never enters the repository (cache outside the tree, `.gitignore` rules, `corpus.py guard` in ctest and in the workflow); https only from the allow-listed hosts; an archive is untrusted data and nothing from it is executed; every exclusion carries a reason and appears in the report; a missing tool is a failure; tolerances are per library in the manifest and are never changed to pass without a written reason.

**Never:** sign in anywhere, accept any site's terms, use credentials or random mirrors; trigger CI; commit corpus files; mark the story done while an AC is unmet.

### 2026-10-27 - VSCO 2 CE null-test triage (second review: root causes of 0 of 48)

Method: reproduce on one 4-region instrument (TubularBells, one note), bisect by note time, block size, SFZ opcode and probe, compare engine and sfizz with an independent exact Hermite resample, simulate sfizz's arithmetic. Seven distinct causes; no engine or importer bug; the previous hypotheses ("retriggered notes", "attack 7x faster") were a mixture of causes 1 and 2.

  - `[high]` `patch` (cause 1, harness input) event times on exact frame boundaries: `sfizz_render` accumulates 1/48000 s per frame and fires an event on the first frame whose sum is >= the event time, so for an event exactly ON a frame boundary the double rounding picks frame N or N-1 (single note at 4800 right, at 14400 one frame early; bisected: the render of the same note at 0.1 s and 0.2 s matched, at 0.3 s did not). A one frame shift of a bright bell transient nulls at -12 dB. The probe MIDI sat on exact boundaries (50 frames per tick). Fix: `midi_suite.py` uses one tick per frame and a first tick of 1.5 frames, so every event is k + 0.5 frames; sfizz fires on floor(t*48000) and the engine (exact integer arithmetic in `smf.cpp`) uses floor too. Unit test `test_midi_suite_events_are_half_a_frame_after_a_frame_boundary`. Evidence: single note at frames 4800 .. 72000: -60.9 dB at every position (was -11.4 beyond 12919 frames).
  - `[high]` `patch` (cause 2, sfizz defect) `ampeg_dynamic=1`: `ADSREnvelope::getBlock` in dynamic mode calls `updateValues(0)` on its first chunk, which overwrites the start delay (the note's frame inside the 64-frame block) of the Delay state with 0, so the 1 ms attack of a note that does not start on a block boundary is cut short: note at frame 4832 -34 dB with the flag, -61 dB with the flag removed from the SFZ (an earlier "removing it changes nothing" cannot have used a note off the block boundary: the defect needs a delay inside the block). By the SFZ definition the flag only makes the envelope re-read `ampeg_*_oncc` / `vel2` values while a voice sounds (the importer rejects those opcodes, so for VSCO it is inert); the engine's specified attack is right. Not tweaked in sfizz and not stripped from the SFZ: the corpus job renders the oracle at block size 1 (cause 3), where the block-relative delay is always 0 (measured: dyn and no-dyn identical, -72.7 dB at three offsets).
  - `[high]` `patch` (cause 3, sfizz imprecision) float32 position sum: `Voice::fillWithData` keeps a voice's read position as int + a float32 cumsum of the per-frame jumps per block, so the rounding of the sum quantises the increment and the playback speed of a 44.1 kHz sample at 48 kHz is about 0.6 ppm off (a numpy model of exactly that sum predicts 0.249 frames at 10 s, the render shows 0.27; the engine, accumulating in double, stays within 0.003 frames of an exact Hermite resample over 10 s). Effect: a 10 s bell nulls at -53.5 dB at the oracle block size 64, -57.4 at 32, -60.8 at 16, -61.6 at 8, -70.8 at 2, -72.2 at 1, growing with note length and pitch (lag grows 0.027 frames/s, relative residual -60 dB at 0.1 s to -29 dB at 6 s). The block size is a command line option of `sfizz_render`, not a change to sfizz: `render-oracle.sh` takes `VELORA_SFIZZ_BLOCKSIZE` (default 64, the Story 1.15 / 5.2 suite is unchanged) and the corpus job runs oracle and engine (`--oracle-block-frames`) at 1 (0.5 s for 20 s of audio). The engine's own emulation of sfizz's one-frame position hold (`oracle_block_frames`) stays valid at block 1.
  - `[high]` `patch` (cause 4, comparison) engine tail shorter than the oracle's: `sfizz_render` renders until silence (VSCO `ampeg_release` is up to 15 s) while the probes asked the engine for 1.5 .. 3 s, so energy outside the compared overlap (-24 dB) failed `--check-excess` and the residual compared a truncated tail. The runner now measures the oracle file and renders the engine with exactly that tail (no more: at block size 1 `sfizz_render` stops at the first near-silent frame, and a longer engine tail counted as excess energy -59.7 dB).
  - `[high]` `patch` (cause 5, comparison) 16-bit oracle floor: sfizz writes 16-bit with dr_wav's truncating conversion, a rounding noise of about -101 dBFS per sample (measured 0.29 LSB rms), which for a quiet instrument is the whole residual (OboeSusNV `round_robin`: mean level about -47 dBFS, residual constant -101.1 dB per window, -54.4 dB total; with every real difference below 0.3 LSB). `velora-null-test --candidate-quantize sfizz-s16` (new, only with `--reference-decode sfizz-s16`) runs the engine's float through the same conversion and the same decode before comparing: a deterministic model of the oracle's output stage, no statistics. The Oboe probe goes to -88 .. -97 dB (99.9 % identical samples). Unit test `test_quantize_like_sfizz_s16`, ctest `null_test_candidate_quantize_needs_reference_decode`, README.
  - `[medium]` `patch` (cause 6, sfizz RNG, not comparable) random layers: instruments using `lorand/hirand` (FluteStac, TrumpetStac, 19 of 75 files) play different layers in the two renderers: sfizz's `Random::randomGenerator` is a fixed-seed Numerical Recipes LCG (`fast_rand`, seed 0, no setter; note that it is a `static` in a header, so each translation unit has its own copy) drawn once per note-on, note-off and CC by `Synth.cpp`, the engine's is a seeded xorshift drawn once per note-on and note-off, so no seed makes them agree (residual about 0 dB). Proof that the RNG is the only cause: FluteStac with the second random layer removed from the SFZ nulls at -50.1 .. -59.1 dB (block 64, before causes 1-5 were fixed). Disposition: documented by design (the same position as the synthetic `random_layers` case, whose paired regions carry identical audio). `corpus.py` leaves such instruments out of the null picks while a deterministic instrument exists and lists them in the report (`null_excluded_random_layers`); they are still imported. Unit test `test_random_layer_detection_and_null_pick`. Not done: replicating sfizz's LCG and draw order in the engine (sfizz-specific coupling in the product engine).
  - `[medium]` `patch` (cause 7, quiet material) GM-StylePerc.sfz, the quietest instrument of the library (mean about -60 dBFS, noise-like samples): even on the common 16-bit grid a float difference of about 0.02 LSB (no lag, gain 1.00003 on both channels) becomes 1 to 4 percent single-LSB mismatches, which cost linearly in the residual (-49.4 `round_robin`, -50.0 `releases`, -54.5 `sustained_loops`; all other probes -68 .. -77). Recorded per-instrument tolerance in the manifest (`tolerance_overrides`, -45 dB, with the reason, a stale path fails the job, the report prints it); the global -60 dB is untouched. Unit test `test_tolerance_overrides_need_a_reason_and_a_real_path`.
  - result: VSCO 2 CE 8 instruments x 6 probes: before 0 of 48 (-54.4 .. +1.9 dB), after 38 of 48 (-49.4 .. -99.0 dB); the 10 failing probes are FluteStac (4) and TrumpetStac (6) (cause 6). Per instrument after: TubularBells -63.9 .. -72.1, Contrabass -70.1 .. -99.0, Oboe -88.2 .. -97.0, Tuba -87.0 .. -95.9, FHorn -72.1 .. -86.3, GM-StylePerc -49.4 .. -77.1 (tolerance -45), FluteStac -0.5 .. +1.4 on four probes (-70.1, -72.1 on the other two), TrumpetStac +1.3 .. -15.3.
  - `[low]` `defer` the Mac-only evidence: the oracle, the engine and the corpus run on the Mac (arm64); the float32 sum of sfizz is IEEE-deterministic but the block-size effects were not measured on Linux.
