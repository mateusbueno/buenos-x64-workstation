## Intent

**Problem:** Converting multi-gigabyte SFZ or SF2 sound libraries on the physical instrument's embedded CPU would tie up DSP audio rendering or take hours. Keyboardists want to convert large sample libraries on their Mac/PC using Studio's full multi-core performance, organize their library catalog by category, and prepare bundles offline for fast USB deployment.

**Approach:**
1. Provide a desktop library converter backend in `desktop/src-tauri/src/converter.rs` that interfaces with `formatlib` / `librarian` conversion engine, producing byte-identical lossless `.velorabundle` packages without any decryption capability (verified by `check_format_no_decrypt.py`).
2. Implement Tauri IPC commands:
   - `list_converted_libraries`: lists local bundles in `<app_cache>/converted_libraries/` with category, size, instrument count, and source metadata.
   - `suggest_import_categories`: runs the 17-category suggestion algorithm on file/directory names.
   - `start_library_conversion`: runs multi-threaded conversion worker with per-file progress events (`converter://progress`).
   - `cancel_library_conversion`: cancels ongoing conversion and unlinks partial bundles from disk.
   - `delete_converted_library`: removes converted bundle from local computer cache.
3. Build `LibraryViewController` and accessible DOM view in `desktop/src/library_view.js` and `library_view_dom.js`:
   - Opened from LIBRARY sidebar heading ("Manage library").
   - Displays two tabs/sections: "On Velora" (device-installed, grouped by category) and "On Computer" (converted libraries).
   - "Import & Convert SFZ/SF2" dialog with category selector (17 canonical categories with "(Suggested)" indicator and "Apply to all").
   - Live progress indicator with Cancel button.
4. Verify parity between computer-converted bundles and device-importer bundles for `library_id`, `instrument_key`, and decoded audio bit-identity.

## Boundaries & Constraints

**Always:**
- Converted bundles must have identical `library_id`, `instrument_key`, and lossless decoded audio as bundles generated by the on-device importer.
- Categories must be assigned to one of the 17 canonical categories (1..17).
- Cancelled conversions must leave zero partial bundles in the local cache.
- Desktop verify build must contain zero cipher/decrypt symbols (passes `check_format_no_decrypt.py`).
- All UI strings localized in `en`, `es`, and `pt-BR`.

**Never:**
- Never bundle or link decryption keys or `ProtectedBundleReader` into the desktop build.
- Never write corrupted or half-converted bundles into the converted libraries cache.
- Never block the UI thread during multi-file conversion.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Category Suggestion | File name e.g. "Steinway Model D.sfz" | Returns suggested category `category.piano` (Piano) | Falls back to `kNone` if no keyword matches |
| Full Conversion Batch | User selects folder with 3 SFZ files | Converts on worker thread, emits progress events 1/3, 2/3, 3/3 | Displays failure reason for damaged files, continues rest of batch |
| Cancel Mid-Conversion | User hits Cancel during file 2 of 5 | Stops worker thread, deletes temporary output files | Leaves only fully completed libraries or clean empty state |
| Corrupted / Damaged File | Invalid header or missing audio sample | Reports `damaged` reason code in progress log | Skips damaged file without crashing |
| Symbol Verification | `check_format_no_decrypt.py` on verify target | Exits 0: no decrypt or cipher symbols found | CI fails if any decrypt symbol is linked |
