## Intent

**Problem:** Panel LEDs cannot be driven: there is no ws.v1 LED command, no LED_SET frame output from the engine's panel link, toggles do not publish one state with one LED lit per state, and there is no on-screen LED view on the Mac virtual panel (FR111, UX-DR50/51/81, AR10).

**Approach:** Add an additive ws.v1 LED command from ui to engine; the engine's panel reader (sole writer of the panel link) turns it into LED_SET frames through its TX hook and keeps the full LED state; ui owns the three toggles (DRAWBARS/MIXER, PARTS/SCENES: 2 states; PART/ALL/ASSIGN: 3 states cycling PART→ALL→ASSIGN), lights only the active state's LED, publishes toggle state from one place, drives timed patterns (blink twice 2×250/250 ms, single 200 ms recall dip, never >3 Hz), and re-sends the full LED state on (re)connect; the Mac virtual panel exposes an on-screen LED view.

## Boundaries & Constraints

**Always:** Only `engine` writes the panel link; ui sends commands over ws.v1 only. Additive proto (new ClientMessage body number; unknown fields never reused). LED ids/brightness/arg exactly per `mcu/common/MCU-ID-MAP.md` section 8 and ids.json (LED_SET payload: led_id, brightness 0..255, arg). Unknown LED ids are rejected with a ws.v1 error and nothing is sent. Patterns are generated by ui in time (ui sends discrete LED_SET states); no pattern step is shorter than 250 ms except the single 200 ms dip, and no LED toggles faster than 3 Hz. On ui restart ui re-sends the full LED state (engine also replays its stored state to a newly (re)connected MCU, HELLO) and the sound is never interrupted (LED path never touches RT). Reuse existing ui toggle state (Stories 4.23, 4.25, 4.26) and publish it from a single owner object that the Top Bar mirror and mode behaviours read.

**Never:** No pedal/footswitch LEDs beyond what the ID map lists, no hardware I/O, no brightness-setting UI (Story 10.4), no RT-plane involvement, no relay via sysd.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| LED command | ws.v1 SetLed(id, brightness, arg) | engine emits one LED_SET frame via panel TX and stores the state | unknown id → error, no frame |
| 2-state toggle | press DRAWBARS/MIXER | state flips; only active state's LED lit; state published | none |
| 3-state toggle | press PART/ALL/ASSIGN repeatedly | cycles PART→ALL→ASSIGN→PART; exactly one LED lit | none |
| Blink twice | pattern commanded | 2×(250 ms on, 250 ms off), max 3 Hz | none |
| Recall dip | recall pattern | single 200 ms dip then restore | none |
| ui restart | ui reconnects | full LED state re-sent; engine sends it; sound unaffected | none |
| MCU reconnect | panel HELLO again | engine replays stored LED state | none |
| Virtual panel | any LED_SET | on-screen LED view shows the same states | none |
