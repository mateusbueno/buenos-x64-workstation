## Intent

**Problem and approach:** Story 5.3 "SF2 import into the same instrument model" from `_bmad-output/planning-artifacts/epics.md` (starts at line ~3595; read the whole story there, its Given/When/Then acceptance criteria are authoritative and are copied by reference, not paraphrased).

**Constraints:** implement a **clean-room SoundFont 2 reader in `formatlib/`** written from the public SF2 specification (RIFF `sfbk` with `INFO`, `sdta` (`smpl` 16-bit, optional `sm24` low bytes for 24-bit), `pdta` (`phdr`, `pbag`, `pmod`, `pgen`, `inst`, `ibag`, `imod`, `igen`, `shdr`)); no third-party SF2 library is vendored (TinySoundFont/FluidSynth/libsndfile are NOT used); write the format knowledge from the public spec (generator operator numbers, default values, units: timecents, cents, centibels, 0.1% pan, etc.). Add the new files under `formatlib/` with the same conventions as the SFZ importer (typed errors, no exceptions across API, bounded reads, UTF-8 name handling, bounds checks on every chunk size/offset) and reuse the **same instrument model** (`Region` and the Story 5.1 extension table) and bundle writer: each **preset** becomes one instrument with `instrument_key = "bank:preset"` (decimal, e.g. `0:0`, `128:0` for percussion; document the exact normalisation and uniqueness: a duplicate bank:preset in a file is damaged), zones (preset zones x instrument zones, resolved with the SF2 generator-merging rules: global zones, preset generators add to instrument generators for additive ones, instrument-level `keyRange`/`velRange` intersected with preset-level ranges, `sampleID` terminal generator, `overridingRootKey` vs sample root pitch (`byOriginalPitch`), `pitchCorrection` from `shdr`) map to regions: key range, velocity range, root key, coarse/fine tune (`coarseTune` semitones, `fineTune` cents, `scaleTuning` document ignore or implement: implement if the model supports it, otherwise warn), `sampleModes` loops (0 none, 1 continuous, 3 loop until release → loop_continuous/loop_sustain mapping with the loop points from `shdr` start/end loop offsets plus `startAddrsOffset`/`endAddrsOffset`/`startloopAddrsOffset`/`endloopAddrsOffset` and their `Coarse` variants — apply the offsets and validate they stay inside the sample), attenuation (`initialAttenuation` centibels → volume dB), pan (`pan` in 0.1 %), volume envelope (`delayVolEnv`, `attackVolEnv`, `holdVolEnv`, `decayVolEnv`, `sustainVolEnv` (centibels of attenuation → sustain level), `releaseVolEnv` timecents → seconds into the model's ampeg fields), `initialFilterFc`/`initialFilterQ` into the Story 5.1 filter fields (lowpass 2-pole; map absolute cents → Hz; Q centibels → resonance dB; `initialFilterFc` at its default 13500 (~20 kHz) means no filter), `exclusiveClass` (document: ignored with a warning or implemented if the model supports `group/off_by`: warn), stereo samples (`sampleType` left/right linked samples: map each linked pair to a stereo sample or two regions panned hard left/right — pick one and document; ROM samples (sampleType with 0x8000 flag) are damaged/unsupported) and `sampleLink`. **Sample storage:** sample data is stored at its source bit depth and rate (16-bit; 24-bit when `sm24` is present) and decodes **bit-identical** to the SF2 sample data (the bundle writer's int PCM path; verify with tests comparing decoded PCM against the file's `smpl`/`sm24` words, including 24-bit assembly), no resampling or requantisation; one bundle sample per SF2 `shdr` sample actually referenced (dedupe by sample header; regions reference samples by index). **Features outside the model** (non-default modulators `pmod`/`imod` entries other than the default modulator set, LFOs (`delayModLFO`, `freqModLFO`, `delayVibLFO`, `freqVibLFO`, `modLfoToPitch`, ...), modulation envelope generators, `keynum`/`velocity` overrides, `chorusEffectsSend`/`reverbEffectsSend`, `scaleTuning` if not mapped, `keynumToVolEnv*` etc.): **the preset imports with these ignored, never skipped for them**, and the import report lists each ignored item per preset as a **warning** (reuse the 5.1 structured report with a new warning code `ignored_sf2_feature`, preset id, generator/modulator name, file-level counters) — the rule documented in the importer header and in the README and covered by a test (a fixture preset with an LFO, a mod envelope and a custom modulator imports and reports exactly those warnings). **Damaged SF2** (bad RIFF sizes, chunk sizes exceeding the file, `phdr`/`pbag`/`inst`... table size mismatches, bag/gen/mod indexes out of range, sample offsets/loop points outside `sdta`, terminal records missing, `shdr` start>end) → the file is skipped with reason code `damaged` and the failing detail; the batch continues (reuse `librarian import` batch from 5.1: `.sf2` extension routes to the SF2 importer; one SF2 file = one library with N instruments (presets) — define `library_id` (UUIDv5 of the source fingerprint as for SFZ: absolute path + ... keep consistent with 1.13's rule) and `instrument_key` per preset; the bundle holds all presets of the file). Nothing of a damaged file is written. **Tests:** SF2 fixtures are generated in code by a small test-only SF2 **writer** (tests/sf2_builder) producing valid files: (a) a General-MIDI-style bank (several presets across banks, a percussion bank 128, shared samples, stereo pairs, 16-bit and a 24-bit variant, looped and one-shot samples, envelopes, filters, key/vel splits), (b) a single-instrument file; plus negative fixtures for each damage class and fuzz (mutated valid files never crash/hang; bounded memory). A **structural test matches every zone to the source** (the builder records the intended zones; compare against the imported regions field by field after a bundle round trip). A **render comparison against an unshipped reference player (built only in the test job)**: use the existing sfizz oracle toolchain? sfizz does not read SF2: use **FluidSynth** as the oracle ONLY as an unshipped test tool: add `tools/oracle/build-fluidsynth.sh` fetching and building FluidSynth (LGPL — never linked into any shipped target, never vendored; extend `tools/ci/check_third_party_notices.py` oracle rules: sources stay under the git-ignored `.work`, the notices script asserts nothing under shipped targets references it, like sfizz), render the fixtures' MIDI with FluidSynth (`fluidsynth -ni -F out.wav -r 48000 -g gain sf2 mid`, disable reverb/chorus, fixed interpolation, document flags) into committed goldens (small) and null-test the engine's render of the imported bundle against them with a tolerance recorded with the tests (SF2 synthesis details like interpolation, filter and envelope shapes differ; measure honestly and record the achieved residual, target −40 dB or better where possible; where lower, explain why; do not fake); if the oracle cannot be built in this environment (network or toolchain), STOP and report rather than fabricate goldens. The offline renderer gets `--engine sample --bundle B --instrument 0:0` already; check it works with the SF2 bundles. SF2-specific engine behaviour needed by the model (e.g. loop points inside samples, attenuation/pan) must not require changes beyond the Story 5.1/5.2 model; if the model lacks something essential (e.g. exclusive class, scaleTuning), document the gap.

**Never:** vendor or link FluidSynth or any SF2 library into shipped targets, implement SF2 modulators/LFOs in the engine, UI, categories, or change existing goldens.
