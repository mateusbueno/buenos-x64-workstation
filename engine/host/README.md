# engine/host

Role: host/OS adapters (ALSA, UMP, input edge threads, io_uring streaming, OP-TEE, control thread) implementing `engine/ports`.

Dependency rule: may depend on `engine/core`, `engine/ports` and OS libraries; `engine/core` must never depend on it.

## Portable code (all platforms, unit-tested in ctest)

- `time_mapper` -- fixed-scheduling-delay rule: `due = event_ns + delay`; `frame = round((due - block_start) * rate / 1e9)`.
  Late (due before block start) -> frame 0 and counted; beyond the block -> deferred by the renderer;
  beyond the 100 ms horizon -> clamped to the horizon and counted. Monotone, so events are never reordered.
  Default delay 3 ms.
- `midi_ingest` -- normalises UMP words (MIDI 1.0 type 2 up-converted, MIDI 2.0 type 4 passed through) to note on/off,
  stamps them with host time and pushes them on an SPSC queue (single producer = the MIDI thread).
  Non-note messages are ignored and counted; a full queue drops and counts (never blocks).
- `render_driver` -- the audio-thread path shared by the live CoreAudio callback and the device-free tests:
  drain queue -> map timestamp to frame -> `BlockRenderer::submit` -> `process_block`. No allocation, locks or blocking
  (`VELORA_NONBLOCKING`; `rtsan_host_render_test` checks it under RealtimeSanitizer where the compiler supports it).

- `mcu_frame` -- Story 3.1. C++ wrapper (`velora/host/mcu_frame.hpp`) over the portable C library in `mcu/common`: typed messages
  (`Message` variant), `make_frame`/`parse_message`/`encode`, `StreamDecoder` (any chunking, counters, events), and the
  `FrameWriter`/`Loopback` helpers for Stories 3.2/3.5 and the Mac virtual panel. The generated `velora/host/mcu_ids.hpp` holds
  the constexpr control/button/LED ID tables. Control/I-O thread only (it allocates); the C library underneath never does.
- `library_resolver` (+ `fs_port`, `posix_fs`) -- Story 1.14. Resolves `(library_id, instrument_key)` to an opened bundle
  and its instrument entry from the index, never by scanning. Control/I-O thread only (allocates, does file I/O); not for
  the audio thread. Links `velora_format`; `engine/core` does not.
  - Layout (root is a parameter, default `/data`): `<root>/lib/<library_id>/current -> <bundle_id>` (relative symlink,
    one component, 64 lowercase hex) and `<root>/lib/<library_id>/<bundle_id>/bundle.vlb` (`kBundleFileName`, shared with
    `tools/library-gen`). `library_id` is a canonical lowercase UUID string.
  - No-scan rule: the resolver only does `lstat(current)`, `readlink`, `lstat(<bundle_id>)`, `open(bundle.vlb)`, two `lstat`s (Story 6.5: no
    `bundle.vlrp` or `wrapped-key.bin` may stand beside an unprotected bundle: `protected_downgrade`) and three
    preads (header, manifest, index): a constant 10 filesystem ops (the `close` included) regardless of library count or size, zero directory
    listings, no sample blocks read. All access goes through `FsPort`; `CountingFs` counts ops so tests assert this.
  - Results: `kOk`, `kInvalidId` (rejected before any fs access: non-UUID, `..`, `/`, empty), `kMissingLibrary`
    (absent/dangling `current`), `kMissingInstrument`, `kBundleError` (+ formatlib `Error`), `kInvalidLink` (not a symlink
    to a sibling `<bundle_id>` directory: absolute, nested, `..`, loop), `kIdentityMismatch` (bundle's library_id/bundle_id
    disagree with its path). A failed resolve never substitutes another instrument or library.
  - The returned `shared_ptr<const BundleReader>` keeps the file descriptor open (the lease) until released. Opening reads the
    whole index into RAM (formatlib behaviour); fine for the test bundles, to be revisited for very large single bundles.
  - Tests: `library_resolver_test` (every matrix row, op-count equality across 10 / 1,000 (1 GiB sparse each) / 3,000 (20,000 opt-in)
    libraries, no-readdir and only-requested-paths assertions). Default scale is 10 / 1,000 / 3,000 libraries; set `VELORA_SCALE_TEST=1` to add the 20,000-library case (~30 s to generate). Timings it prints are "host, not representative".

- `sample_bundle_loader` -- Story 1.15. Decodes every sample of one bundle instrument into RAM as planar float (integer PCM
  `value / 2^(bits-1)`, float32 bit for bit; no resampling or requantization) and exposes it with the region table through the
  `engine/ports` sample-source port (`BundleInstrument`) for the `SampleEngine`. Control thread only (allocates, decodes). A sample
  that fails to decode is left empty and counted (`failed_samples()`), so the engine skips and counts its regions instead of playing
  garbage; an unknown `instrument_key` is `kInstrumentNotFound` and nothing else is substituted. Test: `sample_bundle_loader_test`.

## Live Set format and store (Story 4.2, in `velora_control`)

The persisted Live Set is the protobuf `velora.liveset.v1.LiveSet` (`proto/live_set.proto`; the file format, distinct from the
`ws.v1` wire protocol, reusing its `InsertSlot` and `PartOutput`). `velora/host/live_set_store.hpp` is the control-thread side
(control/I-O threads only, never audio; protobuf stays out of `engine/core`).

- **Schema.** `format_version` (current N = 1), `id` (UUIDv4, canonical lowercase), `name` (1..64 bytes), `tempo` (the range of registry `tempo_bpm`, 20..300 bpm; read from the generated registry),
  exactly the tier's part count of `Part`s (8 v1, 16 Pro), 0..8 `Scene`s, `assign` (exactly 8 slots, 0 = empty, else a
  *performance* `param_id`) and `master` (master-scope registry params). A `Part` holds `timbre` `(library_id, instrument_key)`
  or unset, `low_key`/`high_key` 0..127 (low <= high), `octave` -4..4, `transpose` -12..12 semitones, `keyboard_on`, `volume` 0..1,
  `output` Main/Aux, `inserts` (<= 5 `ws.v1.InsertSlot`), `send_reverb`/`send_delay` (registry 400/401 ranges), `engine`
  (`engine_type_id` + `(param_id, value)` list: no per-engine message, so FM/VA fit), `envelope` and `eq` (lists of registry
  part-scope params) and `arp` (`ArpSettings`: enabled, pattern, rate, gate, octave_range, hold, swing; all optional, unset in v1,
  names from Epic 7 stories 7.2-7.4; using them needs no version bump or migration).
- **Scene semantics.** A scene is a full parameter snapshot *excluding the timbre assignment*, stored sparsely: each `ScenePart`
  field is `optional` (presence flag) and the `engine_params`/`envelope`/`eq`/`master` lists override by `param_id`; an `InsertChain`
  wrapper replaces the whole chain; `arp` merges field-wise. Anything absent takes the base Live Set's value. A scene never holds the
  timbre, the engine type, the tempo (Live-Set-scoped, Story 7.4) or the ASSIGN map (Live-Set-scoped, Story 4.10: it travels with the generation, not with a scene).
- **Determinism.** No map fields; serialisation uses protobuf's deterministic mode (fields in number order, unknown fields last)
  (`serialize()`; golden `tests/golden/live_set_fixed.bin`). read -> write is byte-for-byte identical only for files in canonical
  form, i.e. written by this schema's writer. A rewrite canonicalises: field order (a file from another producer with unknown
  fields interleaved gets them moved after the known ones, still preserved), default-valued proto3 fields are dropped, a present
  but empty `timbre` becomes unset, and an N-1 file is written as N.
- **Reading.** `parse`/`read_file` (file <= 1 MiB, regular file, no symlink) return a closed `Status` (`kParseError`, `kTooLarge`,
  `kUnsupportedVersion`, `kInvalid`, ...) and a `ValidationReport` (typed `IssueCode`s; no exceptions across the API). Version
  policy: N and N-1 load (N-1 goes through the `migrate` stub, which today only moves `format_version`), everything else
  (including 0/unset) is `kUnsupportedVersion`. Tests exercise N-1 by giving the reader `current_version = 2`.
- **Forward compatibility.** Unknown fields are kept in the parsed message and written back. An unknown `param_id` (or insert type)
  is preserved and listed in `report.unknown_params`, never rejected. Out-of-range values, wrong scope (a master id in a part list,
  tempo in `master`), duplicate ids, non-integral enum/int values, NaN/inf, wrong part count, > 8 scenes, an ASSIGN of another
  length or naming a known structural parameter are errors (`kInvalid`, nothing written). Class rules: the part lists (`engine`, `envelope`, `eq`, scene overrides) take
  *performance* part-scope params only (the structural `part_output`/`timbre_ref` have their own field / are the timbre assignment:
  `kWrongClass`); the master lists take master-scope params except `tempo_bpm` (own field; `kWrongScope`) and `line_in_level`
  (device input; `kWrongClass`). Strings (names, `instrument_key`) must be valid UTF-8; `instrument_key` must not be absolute,
  contain a backslash or a `..` segment. A scene's `low_key`/`high_key` override is checked as the effective pair against the base
  part. Enum values above this build's range (`PartOutput`, `ArpPattern`, `ArpRate`) and insert slots of an unknown type (their
  params are not range-checked) are preserved with a warning (`kUnknownEnumValue`, `kUnknownInsertType`), never rejected.
- **IDs.** `mint_uuid_v4(RandomSource&)` (`OsRandom` = `/dev/urandom`, `SeededRandom` for tests; no RTC). Fails closed: a failing source yields no id (`mint_uuid_v4` returns "").
  `adopt_with_collision_check(ls, existing_ids, rng)` gives a colliding (or malformed) id a fresh UUIDv4 and keeps the content; at most 16 draws, then `kFailed` with the Live Set untouched.
- **Resolution report.** `resolve_parts(ls, availability)` returns per-part `kOk` / `kEngineNotAvailable` (reserved engine with
  none compiled, e.g. FM/VA, or an unknown type: silent, never substituted) / `kTimbreEmpty` (a Sample part with no timbre)
  without loading anything; `availability_of(EngineRegistry)` snapshots the bound engine ids (it does not keep the registry).
- **Store.** `LiveSetStore::open` takes an exclusive `flock` on `<dir>/.writer.lock` (a second store, even in the same process, gets
  `kWriterBusy`) and records the calling thread as *the* control thread; `write` (the single writer entry point) and `reconcile`
  from any other thread return `kNotControlThread` (handover is explicit: `rebind_control_thread()` from the new thread; thread ids may be reused after a thread exits, so keep one long-lived control thread); `read` is allowed anywhere and refuses (`kInvalid`) a file whose embedded id differs from its filename. `write` validates, then: temp file
  `<id>.liveset.tmp` in the same directory, fsync (F_FULLFSYNC on macOS), rename over `<id>.liveset`, fsync the directory. The
  directory must be on the journaled partition. `kCommittedNotDurable` means the rename happened (new file in place) but the directory fsync failed. A crash leaves the old file or the new one; leftovers `*.liveset.tmp` are removed by
  `reconcile` (which returns `kIo` if a leftover could not be removed). `StoreOptions::on_stage` is the fault-injection hook (tests `_exit` in a forked child at each stage).
- **Corpus.** `tests/corpus/live_sets/*.liveset` (minimal, full 8-part with 8 scenes and ASSIGN, FM/VA parts, missing library,
  Pro 16-part, unknown fields from a newer schema) were written by this release; `live_set_tests` opens every file on every build,
  checks it is byte-stable under read -> write and equals what the fixtures produce today (drift fails the test). Regenerate with
  `cmake --build build --target live_set_corpus_regen` (also rewrites the golden file) only when a change is intended.
- Tests: `live_set_tests` (round trip, golden bytes, every validation rule, scene semantics, version policy, unknown-field
  preservation, reserved engines, UUIDs and collisions, atomic write with crash injection, single writer, hostile input incl. a
  deterministic mutation/garbage fuzz, corpus). protobuf logs one stderr line per invalid-UTF-8 string the fuzz feeds it.

## Live Set load (Story 4.3, `velora_control`)

`velora/host/live_set_loader.hpp`: `LiveSetLoader::load(live_set)` / `load_file(path)` turn a Live Set into ONE new snapshot generation of the engine and swap it in only when every part's instrument is resident. Control thread only; the voice-pool reservation (`VoiceArbiter::reserve()`) must run while the audio callback is not rendering, so `load()` is for start-up (engine-host does, before audio starts) or between renders in tests. Switching a Live Set while audio renders, with the load in the background and the reservation applied by RT at the swap, is Story 4.5 ("Seamless Live Set switching" below); the preload of the next Live Set is Story 4.7.

- **Steps.** (1) validate against the tier (`LiveSetLoaderOptions::part_count`, 8 on v1: a 16-part file on a v1 tier is `kInvalidLiveSet`/`kBadPartCount`; a Pro tier accepts 16, but this build's engine carries `core::params::kPartCount` = 8 parts, so **Pro 16-part Live Sets are rejected with `kPartCountUnsupported`** — a typed refusal that publishes nothing; supporting them needs a larger engine part count); (2) per part resolve the timbre `(library_id, instrument_key)` through the `LibraryResolver` (Story 1.14) and make the instrument resident through a `HeadProvider`; (3) build the generation: zone, octave, transpose, keyboard flag, volume, output, insert chain (effect instances built here, off the RT thread), sends, engine type, engine/envelope/eq sound parameters (registry performance ids become the generation's initial values), master settings and tempo; (4) compute the Live Set's voice-pool reservation (`fill_fx_costs()` of the new generation, `OrganEngine::reservation_cost_units(organ parts)`, a 256 voice sample floor when there is a sample part; no sample part = floor 0, no organ part = no organ reservation); (5) check the control plane's FX budget and ledger (`ControlPlane::can_publish()`), reserve, publish (`ControlPlane::publish_snapshot()`).
- **Two halves (Story 4.5).** `load()` is `stage()` + a quiesced commit. `stage(live_set, StageControl, out)` does all the slow work (steps 1-4; it changes nothing of the engine and may run on a worker thread); `commit_seamless(staged)` (control thread, audio may render) prepares the reservation and publishes the generation carrying it. Details below.
- **Quiescence.** `LiveSetLoaderOptions::is_rendering` (optional callback) is asked first; when it says the audio callback is rendering, the load is refused with `kNotQuiesced` before anything is touched. engine-host answers "the audio stream has started" (so the Live Set is loaded before `audio.start()`); the offline renderer renders on the calling thread after the load. Unset = the caller guarantees quiescence.
- **All or nothing.** Nothing is published, and the arbiter reservation stays as it was, when a resolved instrument cannot be made resident (`kInstrumentLoadFailed`, `failed_part`, `load_status`), the arbiter refuses the reservation (`kArbiterRejected`, `reserve_status`), the effects cost more than the FX budget (`kFxBudgetExceeded`) or no ledger slot is free (`kBusy`). The previous generation keeps playing. (If the last step fails after the reservation, the arbiter's previous `LiveSetConfig` — snapshotted from `VoiceArbiter::config()` before `reserve()` — is reserved again exactly, or the reservation is cleared if there was none.) Scalars read from the file (volume, sends, tempo, parameter values) are clamped to their registry range, non-finite ones take the default, before they reach the generation.
- **Part states, never a substitute.** A timbre whose library or instrument does not resolve leaves the part silent with `PartState::kMissingLibrary` (`PartLoadReport::resolve` says which `ResolveStatus`); a reserved engine type with no compiled engine (FM, VA) is `kEngineNotAvailable`; a sample part with no timbre is `kEmptyTimbre`; an organ part needs no timbre. These are states of the part, not load failures: the Live Set loads and the other parts play. Without a sample engine bound, sample parts are `kEngineNotAvailable`.
- **`HeadProvider` seam.** `HeadProvider::load(resolved, out)` returns a RESIDENT `BundleInstrument`. `RamHeadProvider` (the Mac path) decodes whole instruments into RAM through `sample_bundle_loader`; an instrument with a sample that fails to decode is not resident (`kBundleInconsistent`). Heads, streaming and locked RAM (Stories 1.16/1.17) are board work and implement the same interface. The same (library, instrument) in two parts is made resident once and shared; each part still gets its own bank.
- **Engine per part, sound routing.** See `engine/core/README.md` ("Live Set parts, zones, layers and splits"): banks in the one SampleEngine, the keyboard-channel convention, the `PartRouter`.
- **Not here.** Setlists, UI. The generation does not contain the scenes (the ASSIGN map IS carried, `Snapshot::assign`, Story 4.10); with `LiveSetLoaderOptions::scenes` set the loader hands the Live Set to the `SceneController` (below) after a successful publication. Without it scenes are ignored, as in 4.3.
- **engine-host.** `engine-host --live-set FILE --library-root DIR` binds the sample engine (340 voices) and the organ, loads the Live Set before audio starts as the first generation (the dev configuration is not published when `--live-set` is given, and the pool is reserved for the whole Live Set instead of the flat FX budget), prints each part's state, and exits 1 with the reason when the load fails. `--library-root` is the root of the library layout (`<root>/lib/<library_id>/current`).
- Tests: `live_set_loader_tests` (synthetic `BundleWriter` libraries in a temp root: layer, split at B2/C3, keyboard off, octave/transpose pitch, volume, missing library and instrument, FM/VA/organ parts and the reservation, no-sample-part floor, no sample engine, replacing a Live Set, fault-injected atomic publication with the old generation still playing, arbiter/FX-budget/capacity refusals, tier part counts, the corpus files, bad files).

## Seamless Live Set switching (Story 4.5, `velora_control`)

`velora/host/live_set_switcher.hpp`: `LiveSetSwitcher` (control thread owner; it registers itself as the plane's `SwitchHandler`) jumps to another Live Set **while the current generation keeps playing**: `jump_to(id)` returns at once with a typed result, the target's heads are made resident by a **background worker thread** (non-RT; never the audio threads and never the control thread's command handling), the control thread publishes the new generation only when every head is resident, and RT swaps at a block boundary and applies the new voice-pool reservation in the same step.

- **Who does what.** Worker: read the target's file, `LiveSetLoader::stage()` (validate, resolve every timbre, **size the heads from the bundle indexes before loading** and refuse early when they exceed `SwitcherOptions::head_budget_bytes`, bring the distinct instruments resident through `HeadProvider::load_controlled()` with cooperative cancellation and progress, build the generation, the effect instances and the reservation config); it never touches the plane, the arbiter or the scene controller. Control thread: `jump_to()`, `cancel_load()`, `tick()`. `tick()` harvests the finished stage, runs `LiveSetLoader::commit_seamless()` (`VoiceArbiter::prepare_reservation` + `can_publish` + `publish_snapshot`; all or nothing, nothing changes on any refusal) and republishes the loading status. RT: `BlockRenderer::adopt_generation` adopts the generation and `VoiceArbiter::commit_prepared` installs the reservation in the same serial phase (engine/core README, "Seamless handover"; `Snapshot::reservation_epoch`). The `tick()` is the **control server's poll tick** (`ControlServer::set_tick`, every <= 20 ms; engine-host wires it): a `true` return pushes a State to the subscribers.
- **Old/new voice overlap.** Notes held, sustained by the pedal or releasing at the swap finish on the old generation: the `PartRouter` records pitch, part and engine per key and the note off goes there whatever the new layout is; voices keep their sample bank; the old generation (snapshot, banks, the `BundleLease` the `RamHeadProvider` instrument holds, effect instances) is freed by `ControlPlane::reclaim()` only when RT reports no voice referencing it (ledger / hazard pointer, as for any generation). The part buses, inserts, sends and master follow the new generation immediately. The pedal that is down at the swap also holds the new Live Set's notes. If the 32-slot ledger is full (generations pinned by sounding notes) the commit is retried on each tick for `busy_retry_s` (5 s) and then reported as failed with reason `busy`; nothing is cut meanwhile.
- **Loading status** (`State.loading`, also `GetState`; `status()` in C++): `state` idle / loading / ready / failed, `loading`, target id and name, `estimated_remaining_seconds` (finite, >= 0), `progress` (0..1, bytes resident / bytes of the target), `last_error` + `last_error_informational` + detail, `status_seq`, `cancelled_loads`. While a load runs `tick()` republishes at least every `publish_interval_s` (0.5 s, so at least once per second); the progress comes from the `HeadProvider` progress callback through the stage, the ETA is rate based on the bytes made resident per publication window, smoothed (`rate_smoothing`), with `assumed_bytes_per_second` before a rate exists. The clock is injectable (`SwitcherOptions::clock`); tests drive it with a fake clock and a throttled provider (no sleeping, no timing assertion). `State.live_set_id` / `live_set_name` say which Live Set sounds.
- **Program change.** The swap forces every performance slot to the new Live Set's initial value (`BlockRenderer::adopt_generation`): a knob moved live under the old Live Set never leaks into the new one; scene recalls keep their forced-slot mechanism. The router tags keys with the bank generation of their part, so a key held on the old bank and one struck on the new bank never share a release count.
- **Second jump.** A jump to another target while one loads **cancels** the first (the token is checked between chunks of 64k frames, samples and instruments, and inside the provider's read loop; the stage releases its partial heads before it returns; a finished stage nobody committed is destroyed on the control thread), counts it in `cancelled_loads` and loads the new target; the sound is not touched (a test compares the audio bit for bit with a rig that never saw a jump, up to the commit). The same target twice is `kAlreadyLoading` (not restarted); the Live Set that already sounds is `kAlreadyLoaded`, a no-op (if a load is running it is cancelled: how the player goes back). `cancel_load()` / `CancelLoad`: informational `LOAD_CANCELLED`, state idle.
- **Head budget and typed errors.** The target's total decoded bytes, summed from the index (`HeadProvider::estimate_bytes`, `instrument_head_bytes()`), against `head_budget_bytes` (the Mac default is large; the tier's value comes with Story 4.1): refused **before anything is loaded** with `HEAD_BUDGET_EXCEEDED` (details `head_bytes`, `head_budget`) and guarded again while loading. The budget bounds the TARGET's heads; the generation that keeps playing stays resident too, and the shared accounting (current + next) is Story 4.7. Unknown id: `NO_SUCH_LIVE_SET` (also the `JumpToLiveSet` error reply). Everything else that fails (unreadable or invalid file, an instrument that cannot be made resident, the voice pool or FX budget refusing, a full ledger) is `LIVE_SET_LOAD_FAILED` with a reason (`read_failed`, `invalid_live_set`, `part_count_unsupported`, `instrument_load_failed`, `arbiter_rejected`, `fx_budget_exceeded`, `busy`, `internal`). In every case the current Live Set keeps playing and nothing is published.
- **ws.v1** (additive): commands `JumpToLiveSet{id}` (reply `JumpReply{result ACCEPTED | ALREADY_LOADED | ALREADY_LOADING, target_id, target_name, superseded_previous}` with the `request_id`) and `CancelLoad` (reply `CancelLoadReply{cancelled}`), `State.loading` / `live_set_id` / `live_set_name`, error codes `HEAD_BUDGET_EXCEEDED`, `LOAD_CANCELLED`, `NO_SUCH_LIVE_SET`, `LIVE_SET_LOAD_FAILED`; see `proto/README.md`.
- **Catalog.** `scan_live_set_dir(dir)` lists the `<id>.liveset` files of the `LiveSetStore` directory (id, name, path; invalid files are skipped and reported) and `catalog_entry_for_file()` reads one file; `set_catalog()` / `add_to_catalog()` give the switcher its ids. `engine-host --live-set-dir DIR --library-root ROOT` lists the directory (a `--live-set FILE` missing from it is added; the switcher exists for any Live Set start; `--no-audio` is a dev/test-only flag that runs the control plane, switcher and server without CoreAudio/CoreMIDI, used by the smoke tests), starts with `--live-set FILE` or else the first Live Set by name, and wires the switcher and its tick.
- **Deterministic mode.** `SwitcherOptions::background_thread = false` runs the stage inside `jump_to()` and `hold_ticks = N` publishes the generation at the (N+1)-th `tick()` after the jump (a simulated load time in blocks); same code path, no thread. `velora-offline-render --switch-at` uses it (`tools/offline-render/README.md`).
- **HeadProvider.** `load_controlled(resolved, out, LoadHooks)` (cancel flag + progress callback returning false to stop) and `estimate_bytes()` are the 4.5 additions to the seam; a provider used from the worker is used by one thread at a time. `RamHeadProvider` reads in chunks of `kLoadChunkFrames` and its instrument keeps the opened bundle (the lease) until the instrument is freed.
- Tests: `live_set_switcher_tests` (background load with the old generation answering the keys, all-or-nothing swap, held / sustained / releasing notes across the swap checked against the sum of the old and the new Live Set's own performances, freeing of the old generation with weak sentinels and bundle leases, cross-layout note offs, second jump cancelling the first with a bit-identical audio check and no leaked heads, jump back / same target, head budget early and while loading, typed failures, arbiter refusal, loading status cadence with a fake clock and a throttled provider, full ledger retry, reservation applied by RT at the swap only, ws.v1 over a socket, provider cancellation and sizes, rapid jumps), `switch_rt_traffic_test` / `rtsan_switch_test` (160 switches between four Live Sets with different reservations, a third of them with a cancelled first load, beside dense keyboard traffic and the pedal; the latter under RealtimeSanitizer, Docker/Linux clang only), `engine_host_switch_smoke` (the real engine-host with audio, macOS), offline golden `switch_*` in `tools/offline-render`.

## Setlists, setlist tags and Live Set stepping (Story 4.6, `velora_control`)

`velora/host/setlist_store.hpp` (persistence + commands, `SetlistStore`) and `velora/host/setlist_controller.hpp` (the loaded setlist, stepping and the ws.v1 handler, `SetlistController`). Control thread only; protobuf stays out of `engine/core`.

- **Persisted forms** (`proto/setlist.proto`, package `velora.setlist.v1`): `SetlistTag{id, name}`, `Setlist{id, name, ordered live_set_ids, tag_ids, format_version}`, `SetlistLibrary{format_version, tags, setlists}` and `AssignDefault{format_version, assign[8]}`. Same rules as the Live Set format: only grows by addition, readers accept N and N-1 (N-1 migrated in memory by a stub), anything else is `kUnsupportedVersion`, unknown fields are kept on re-write (library, tag and setlist level; reorders move whole messages), deterministic serialisation (golden `tests/golden/setlist_library_fixed.bin`), files at most 1 MiB.
- **Layout (chosen).** `<data>/setlists/setlists.library` holds ALL tags and setlists in ONE file; the order of the setlists in it is their position (no separate `position` field), so every command is one atomic replace and no command can leave two files out of step. `<data>/setlists/assign_default.pb` is the global default ASSIGN map (absent = built-in factory default) and `.writer.lock` the exclusive lock. The Live Sets stay in `<data>/live_sets/<id>.liveset` (the `LiveSetStore` directory). `engine-host --data-dir DIR` creates `DIR/live_sets` and `DIR/setlists` if missing and wires everything; `--live-set-dir` alone keeps working (no setlists; the two flags exclude each other). A fresh data root with no Live Set starts on the dev configuration (flat FX reservation, engines bound) with the switcher, stores and controller running, so `CreateLiveSet` + `JumpToLiveSet` bootstrap an empty install. Store-open failures print the status name and leave through normal teardown; `reconcile()` failures are warned about.
- **Write discipline.** The Live Set store's, shared through `atomic_replace_file()` (temp file created exclusively without following links, fsync / `F_FULLFSYNC`, rename, directory fsync; `kCommittedNotDurable` = renamed but the directory sync failed: the new state IS in place and is adopted). Single writer: `SetlistStore::open` takes the `flock` on the setlists directory and records the opening thread as the control thread; every command from another thread is `kNotControlThread` (explicit `rebind_control_thread()`). engine-host opens the stores on the main thread and hands them over to the `ControlServer` thread (`ControlServer::set_thread_start`), which is the control thread that runs the commands. A library or default-ASSIGN file that exists but cannot be read (parse error, unsupported version, invalid) fails the open and is NEVER overwritten (engine-host exits 1 and says so).
- **Rules.** Names (setlists, tags) are 1..64 bytes of valid UTF-8 without control characters (not required to be unique). Ids are UUIDv4 minted by the store (fails closed without randomness). A Live Set appears at most ONCE in a setlist (`DUPLICATE_LIVE_SET_IN_SETLIST`) but may be in several setlists. Adding a Live Set the engine does not know is `NO_SUCH_LIVE_SET`; a reference whose Live Set later disappears is kept and flagged `missing` in the state (`SetlistEntry.missing`, `SetlistSummary.missing_count`), never dropped silently. Every tag id on a setlist exists. Limits: 100 setlists, 64 tags, 256 Live Sets per setlist, 8 tags per setlist (`LIMIT_REACHED`), so every reply fits a ws.v1 frame. Reorders are permutations (`INVALID_ORDER`).
- **Commands are atomic.** Each is applied to a copy, validated, written, and only then adopted and published (revision +1); a refusal changes nothing (file, state and revision untouched, tested). Deleting a setlist never deletes a Live Set (the loaded setlist is unloaded; the sound is not touched); deleting a tag removes it from every setlist; deleting a Live Set (`DeleteLiveSet`, `SetlistStore::delete_live_set`) removes it from every setlist in one write FIRST and then deletes the file (a crash in between leaves an unlisted Live Set, never a dangling reference without a record), cleans references to Live Sets whose file is already gone, and is refused for the Live Set that sounds or is loading (`LIVE_SET_IN_USE`). A file that is not named `<id>.liveset` is deleted through the catalog's path when it is a `.liveset` file directly in the Live Set directory, else refused (`STORAGE_FAILED`, reason `path_outside_live_set_dir`). If the file cannot be removed after the setlists were cleaned, the reply is `STORAGE_FAILED` with details `partial=references_removed_file_kept` and `removed_from_setlists`; the revision moves and the State is pushed, the Live Set stays in the catalog.
- **New Live Set** (`CreateLiveSet`, `SetlistStore::create_live_set`): fresh UUIDv4 (not an existing file), the tier's 8 empty Sample parts, ONE scene named "Scene 1" (all-base), tempo 120, and the ASSIGN map **copied** from the default; changing the default never alters existing Live Sets. Written by the `LiveSetStore` (its atomic write and single-writer rules) and added to the switcher's catalog.
- **Default ASSIGN map.** Factory default K1..K8 = `send_delay_level` (401, the DELAY function), `send_reverb_level` (400), `percussion_volume` (113), `percussion_decay` (112), `key_click` (116), `leakage` (117), `rotary_speed` (200), `vibrato_chorus_type` (115): performance parameters of the current registry, to be replaced by the knob functions (brightness, attack, release, EQ) as those parameters appear. `SetlistStore::set_default_assign()` validates (8 slots, 0 or an assignable performance parameter) and writes it; Story 4.10 puts the ws.v1 commands on it ("ASSIGN maps with a global default" below).
- **Loaded setlist and stepping** (full semantics in the `setlist_controller.hpp` header comment). `LoadSetlist` makes a setlist the loaded one and loads nothing: the generation that plays keeps playing, the first Live Set loads when the player steps or chooses (loading the loaded setlist again is a no-op; `UnloadSetlist` goes back to All Live Sets). `State.setlists` carries `loaded_setlist_id`, `last_setlist_position`, `current_live_set_id` (the Live Set that sounds), the `end_of_setlist` / `start_of_setlist` flags, counts, `status_seq` and `library_revision`. The position follows every observed change of the current Live Set (the target of a load in progress, else the sounding one; a step, a plain `JumpToLiveSet`, a Live Set loaded at start): inside the loaded setlist the position becomes its index, outside (an off-script jump) it is left alone, so stepping returns into the setlist relative to it. `NextLiveSet` / `PreviousLiveSet` step to position +-1 (a freshly loaded setlist starts at -1: next is the first, previous is refused) through `LiveSetSwitcher::jump_to` (seamless, background load) and reply `StepReply` with the switcher's typed outcome; at the end "next" does nothing: error `END_OF_SETLIST` (symmetric `START_OF_SETLIST`, `EMPTY_SETLIST`) and the flag latches (a State push, no revision move) until the current Live Set or the loaded setlist changes. A target whose Live Set is missing, unreadable or invalid is `LIVE_SET_LOAD_FAILED` with `reason` (`missing`, `invalid_live_set`, `read_failed`) and **the position does not move and nothing is skipped silently** (the player can choose a later Live Set); failures that only appear while heads load are reported by the switcher in `State.loading` as for any jump, and the position follows the request. The position only moves when the switcher's current Live Set really is the target afterwards; otherwise the step is `LIVE_SET_LOAD_FAILED` with reason `switch_not_applied`. `GetSetlists` flags `missing` by the existence of the file (a catalog entry whose file is gone, or an id that is neither listed nor a valid file on disk), not by catalog membership alone. With no setlist loaded stepping walks **All Live Sets** ordered by name: ASCII-case-insensitive byte comparison (non-ASCII bytes compare as bytes: no Unicode or locale folding), a prefix sorts first, then the id; the same end / start results and flags apply, and from a Live Set not in the list next is the first and previous the last. Removing the anchor Live Set from the loaded setlist re-anchors the position on its predecessor; reordering keeps it on the same Live Set.
- **ws.v1** (additive; `proto/README.md`): `CreateSetlist`, `RenameSetlist`, `ReorderSetlists`, `DeleteSetlist`, `AddLiveSetToSetlist`, `RemoveLiveSetFromSetlist`, `ReorderLiveSetsInSetlist`, `CreateLiveSet`, `DeleteLiveSet`, `CreateTag`, `RenameTag`, `DeleteTag`, `SetSetlistTags`, `LoadSetlist`, `UnloadSetlist`, `NextLiveSet`, `PreviousLiveSet`, `GetSetlists`; replies `CreatedReply`, `LoadSetlistReply`, `StepReply`, `SetlistsReply` (or `Ack`), all with the `request_id`; error codes 22..33. The plane routes them to the `SetlistHandler` seam; without a data directory they answer `INVALID_COMMAND`. Concurrent clients are serialised by the control thread (each command its own revision).
- **Wiring.** `engine-host --data-dir DIR --library-root ROOT [--live-set FILE]`; the control tick runs `LiveSetSwitcher::tick()` and `SetlistController::tick()` (the position follows jumps). `LiveSetSwitcher` gained `sounding_id()`, `effective_id()` and `remove_from_catalog()`.
- **Corpus.** `tests/corpus/setlists/*` (`empty`, `basic` with shared / empty / dangling entries and UTF-8 names, `newer-schema-unknown-fields`, `assign_default.pb`, a custom default) were written by this release; `setlist_tests` opens every file on every build, checks it is byte-stable under read -> write and equals what `tests/setlist_fixtures.hpp` produces today (drift fails). Regenerate with `cmake --build build --target setlist_corpus_regen` only when a change is intended.

## Edits in memory and Write scopes (Story 4.9, `velora_control`)

`velora/host/edit_session.hpp`: `EditSession` (control thread owner; it registers as the plane's `EditHandler`, as the scene controller's before-recall hook and, through `attach()`, as the loader's and the switcher's `LiveSetEditPort`) keeps the in-memory edited state of the Live Sets, publishes which ones are dirty and what changed, and is the only code that turns edits into files, and only for an explicit `WriteLiveSet`. Nothing else writes: playing, scene changes, Live Set changes, edits and setlist stepping perform no Live Set or setlist file write (`LiveSetStore::mutations()` and `SetlistStore::mutations()` count write ATTEMPTS that reached the writer (successful or not, e.g. a full disk) and removes; a test plays a generated hour on a fake clock and asserts both stay at zero and the files' bytes and mtimes do not change). There is no autosave: edits are lost at power-off.

- **Data model.** One document per Live Set id: `saved` (the Live Set message as loaded or last written) and `working` (saved plus every edit). A document exists for the Live Set that sounds and for each Live Set that still has unsaved edits (a clean document of a Live Set that was left is dropped; a document with unsaved edits is dropped only by an explicit `DeleteLiveSet` of that Live Set, never because the catalog transiently lacks the id). Dirty and the change summary are the *semantic* difference between the two (`diff_live_sets()`: values compare with a tolerance of 1e-6 of the parameter's range, an id listed at its default is no change), so an edit moved back to its saved value stops being an edit. Memory: two copies of each dirty Live Set message (<= 1 MiB each).
- **Where an edit lands (mirrors the Write scopes).** While scene S is current, an edit lands in scene S *when S stores that field* (a presence flag set / the parameter id listed in S's sparse overrides, see `proto/live_set.proto`), otherwise in the base Live Set, which every scene that does not override the field inherits; with no scene current it lands in the base. Examples (Live Set "Perfect", scene 2 overrides part 1's volume): scene 2 current and part 1's fader moved -> scene 2's volume of part 1 (Write Scene writes it); scene 2 current and drawbar 3 of part 3 moved -> the base, because scene 2 does not store it (Write Scene does not write it, Whole does); no scene current and a send moved -> the base. The scene controller recalls from the edited source (`SceneController::set_source`: the edited message and the base values rebuilt from it by `fill_part_values()` / `fill_master_values()`, shared with the loader), so a recall gives "the scene's value when it has one, else the (edited) base value": edits are still there when the player changes scene and returns. The 4.4 sentence "a structural command between recalls is overwritten for the fields the scene covers" now holds only without an edit session.
- **What is tracked.** Structural commands that were published (`SetInsertChain`, `SetSendLevels`, `SetPartOutput`, `SetMasterParams`, and the new `SetPartVolume`; the plane tells the session after the commit), `SetPartTimbre`, and performance values the player moves (drawbars, knobs, sends, the tempo...), read from the RT last-value table by `sync_live_values()`: on every control tick, before a scene recall (`SceneController::set_before_recall`), before a Live Set switch publishes (`LiveSetEditPort::before_switch`, called by the loader's commits), on `GetState` and after the fence of a Write. The table is only compared once RT has applied the newest generation (`LastValueTable::load_adopted_revision`, engine/core README), so a recall or switch that RT has not applied yet is never taken for an edit; the line-in level is device input and is not tracked. `SetTimbreRef` (the opaque dev-configuration id) is not part of a Live Set and is not tracked. The ASSIGN map is part of the diff and of Whole / Save as new; Story 4.10's `SetAssignSlot` / `ClearAssignSlot` edit it ("ASSIGN maps with a global default" below; `apply_external_edit()` stays as a general hook).
- **Live Set changes.** The document stays when the Live Set is left; the switcher builds the generation of a Live Set that has unsaved edits from its edited state (`LiveSetSwitcher::set_edit_port`: the overlay is copied on the control thread when the jump starts and the worker stages that message instead of the file), and the loader reports each published generation (`LiveSetEditPort::on_published`). A Live Set that comes back is therefore loaded as edited; the scene is not recalled automatically (a fresh load has no scene current, as in 4.3), the edits of every scene are in the document.
- **State.** `State.edits` (`EditStatus`, additive): `dirty_live_set_ids` (at most 128) and `dirty_count`, the current Live Set's `current_dirty` and `change_summary` (at most 32 `ChangeItem`s with stable `key`, `part`, `param_id`, `scene` and an English `text`; `change_count` is the true number) and `change_summary_text` ("Part 3 volume, Part 1 reverb send, ..."), `has_timbre_edit`, `scene_write_available` / `scene_write_blocked_reason`, `edit_seq`, `writes_done`. The control tick (`EditSession::tick()`, run after the switcher's) returns true when the status changed, which pushes a State. Keys and their meaning: `proto/README.md`.
- **Write (`WriteLiveSet`).** Writes the *current* Live Set only. Order: (1) refusals that need no live values: no Live Set (`NO_LIVE_SET`), a Live Set load or timbre rebuild in progress (`BUSY`, reason `load_in_progress` / `reload_in_progress`), a bad scope, a bad or taken name, Scene without a current scene (`WRITE_SCOPE_UNAVAILABLE`, reason `no_scene` / `no_scenes`); (2) the **control->RT fence** (it also covers the MIDI lane: the render driver holds the fence one block, see engine/core README; after the acknowledgement the newest generation must be applied by RT, else `BUSY` reason `generation_not_applied` and nothing is written): `ControlPlane::raise_fence()` queues a fence event behind every parameter event sent so far and the control thread waits until RT acknowledges it (`EditSessionOptions::fence_timeout_s`, default 2 s, injected `clock` and `fence_idle` hooks: tests pump the render driver, engine-host `--no-audio` renders a block per pass; a timeout is `BUSY` reason `fence_timeout`, a full lane `fence_queue_full`, nothing written); (3) `sync_live_values()` reads the table, so a Save never sees a stale value; (4) the write, per scope, through `LiveSetStore::write` (validate, temp file, fsync, rename; a Live Set whose file is not named `<id>.liveset` is written under that name, the catalog follows and the old file is removed):
  - **Scene**: the saved Live Set with the current scene's stored overrides replaced by the edited ones (only what landed in the scene). Refused with `WRITE_SCOPE_UNAVAILABLE` and the message "Timbre changes are saved with the Live Set" (reason `timbre_change`) while any timbre / engine change is pending. Base edits made in the scene stay dirty (`remaining_changes`); Whole writes them. Clears only the scene's edits.
  - **Whole Live Set**: the whole edited message (base, every scene, master, ASSIGN, timbre). Clears everything.
  - **Save as new**: a copy of the edited state with a new UUIDv4 (minted from `EditSessionOptions::rng`, never an id in the catalog or on disk) and a name, written as a new Live Set file, added to the catalog and, with a setlist loaded, to that setlist right after the current Live Set (`SetlistStore::add_live_set` at its index + 1; if the current Live Set is not in the setlist, after the setlist position; appended when there is none). **The original is untouched and keeps its unsaved edits (still dirty, `current_dirty` in the reply); the new Live Set starts clean**; the sound is not touched (no switch). If the setlist cannot take the entry the new file is removed again (nothing half done). Without a setlist loaded only the file is created. The insertion index is clamped to the setlist size; if the setlist cannot take the entry the new file is removed again and, if that removal fails, the error details carry `leftover_live_set_id`.
  - **Names** (Save as new): trimmed; 1..64 bytes of valid UTF-8 without control characters (`INVALID_NAME`); with a setlist loaded, a name already used in it (ASCII case-insensitive comparison, non-ASCII bytes as they are) is refused `NAME_IN_USE` with `suggested_name` = a free name: an existing trailing " N" is stripped, then "<stem> 2", "<stem> 3"... the first not used in the setlist ("Perfect" -> "Perfect 2", "Perfect 2" with "Perfect 2" taken -> "Perfect 3"), the typed case is kept, cut on a character boundary to 64 bytes, found with one hash lookup per candidate. No name = the suggestion for the current Live Set's name (against all Live Sets when no setlist is loaded). Without a setlist loaded an explicit name is checked against every Live Set the engine lists, the same way.
  - Nothing dirty for the scope (Scene, Whole): no file is touched and the reply says `nothing_to_write`. A repeated Write therefore writes once.
  - **Storage full**: the atomic writer maps ENOSPC / EDQUOT to `Status::kNoSpace` (temp file removed, old file intact) and the Write answers `STORAGE_FULL`; the edits stay in memory with the dirty flag set, and the same Write works once space is back. Test hooks: `StoreOptions::inject_write_errno` / `set_inject_write_errno(ENOSPC)` on both stores. `kCommittedNotDurable` is a success with `not_durable`.
  - Commands are serialised by the control thread (each its own revision); a Write cannot name another Live Set.
- **Timbre edits (`SetPartTimbre`).** Changes the part's timbre / engine type in the edited state (validated like a file: `INVALID_COMMAND` / `INVALID_PART`; the same timbre again is a no-op) and rebuilds the Live Set from it by the seamless path of a switch (`LiveSetSwitcher::reload_current()`: the loader's resolution, residency, reservation and head budget apply; the old generation sounds meanwhile and `State.loading` shows the load; per-part incremental loading is board work with the head cache, Story 4.7). The live values and the current scene are captured first; when the rebuilt generation is published the session recalls the scene again and puts back the live values RT reset (`restoring`, done by `tick()` once RT applied the generation; a refused scene recall (busy) or a full control lane is retried on the next tick, and `restore_timeout_s` (default 5 s) ends the wait if RT never applies the generation). The rebuild is tied to its job (`SwitchOutcome::token`, `LiveSetSwitcher::active_token()`): a rebuild superseded by another jump releases the block at once. While the rebuild runs structural commands, a second timbre edit and Write answer `BUSY` (`reload_in_progress`), so no edit can be lost to it. A performance value moved while it runs is captured when the new generation publishes and restored. A rebuild that fails (head budget, arbiter...) leaves the edit in memory, flagged, and the old generation sounding. A library or instrument that does not resolve plays silent ("Missing library", never a substitute), as for any load. Timbre edits are persisted only by Whole / Save as new.
- **engine-host.** With `--data-dir` the session is created after the stores and wired (`attach()` to the loader and the switcher, control tick). `--no-audio` (dev/test) renders the blocks a fence wait or a rebuild needs.
- Tests: `edit_session_tests` (the fence ordering behind deferred events, a full lane, timeout with a fake clock; dirty flags, summary keys and texts, edits moved back; edits kept across scene changes (base and scene-stored, structural and performance) and across Live Set changes and returns; an unapplied generation is not an edit; Whole / Scene / Save as new with their refusals; the timbre rebuild with the scene and live values restored; name rules incl. a 1,000-name suggestion and UTF-8 cut; storage full for the Live Set file and for the setlist entry; the generated hour with no file write; Write without a Live Set, during a load, repeated, during scene storms, a large edit set within one ws.v1 frame; the ASSIGN hook; a session built after the Live Set sounds), `edit_rt_traffic_test` / `rtsan_edit_test` (3,000 fences behind parameter bursts beside dense traffic, swaps and the pedal; the latter under RealtimeSanitizer, Docker/Linux clang only), `engine_host_edit_smoke` (the real engine-host over ws.v1 with `--no-audio`: dirty flag pushed to a subscriber, Write with the fence, no autosave across a restart, Save as new). No test asserts a duration.

## ASSIGN maps with a global default (Story 4.10, `velora_control` + `engine/core`)

Each Live Set has an 8-slot ASSIGN map K1..K8 (`LiveSet.assign`, 0 = empty, else a registry performance `param_id`); in ASSIGN mode the 8 panel encoders drive the mapped parameters. A global default map seeds new Live Sets. Fixed rules:

- **Legacy files.** A Live Set or `assign_default.pb` written before a parameter became non-assignable (e.g. `line_in_level`) still loads: the validators report the slot as a warning (`report.unknown_params` / `ValidationReport::warnings`), the slot stays in the file and is left out of the generation, and an edit of another slot never fails because of it; only the commands refuse such a parameter (`NOT_ASSIGNABLE`). A structural id in a map is still an error. `State.encoders.assign` shows the GENERATION's map, which can differ from the file's map when the file holds unknown or non-assignable ids; the dirty flag and the change summary are computed from the file's content, so they do not show that difference.
- **Which parameters.** Any registry parameter of class *performance* whose `assignable` flag is true (`proto/params.json`: `"assignable": false` opts out; the default is true for performance parameters and false for structural ones, which have no live value). Today the only opt-out is `line_in_level` (800, device input, not part of any Live Set). Any scope (part, master) is allowed. The Live Set and the default file validators refuse non-assignable ids (`kBadAssignParam`); an id an N+1 writer added that this registry does not know is preserved in the file (warning) and left out of the generation.
- **Duplicates are allowed.** The same parameter may sit in several slots (ids can repeat on purpose; the least surprising behaviour is to do what the player set). No `DUPLICATE_ASSIGN` error exists.
- **Commands (control thread, additive ws.v1, `EditSession::do_assign`).** `SetAssignSlot{target, slot 1..8, param_id}` and `ClearAssignSlot{target, slot}` with `target` CURRENT_LIVE_SET or GLOBAL_DEFAULT. Validation happens before anything changes, in this order: target (`INVALID_COMMAND`), slot (`INVALID_SLOT`, details `slot`, `max_slot`), the parameter (`UNKNOWN_PARAM`; `NOT_ASSIGNABLE` with details `reason` = `structural` | `not_assignable`), then the target: CURRENT_LIVE_SET with no Live Set loaded is `NO_LIVE_SET`, with a load or timbre rebuild running `BUSY` (`load_in_progress` / `reload_in_progress`); GLOBAL_DEFAULT without a data directory (no setlist store) is `INVALID_COMMAND`. Setting the value a slot already has (or clearing an empty slot) is a no-op success: no revision, no write.
- **CURRENT_LIVE_SET = a Live Set edit.** The working copy of the edit session changes (the Live Set is dirty: `ChangeItem` key `assign.slot`, the 0-based slot in `ChangeItem.slot`, text "ASSIGN K1"; an edit moved back to the saved value is no edit), and the map takes effect at once: the session publishes a NEW generation that is a copy of the current one with `Snapshot::assign` changed (same reservation epoch, program generation and initial values, so RT re-applies nothing; the revision moves, subscribers get a State). Scene recalls copy the generation and never change the map; a timbre rebuild or a jump away and back is built from the edited state (the overlay), so the edit is kept. Nothing is written until Write: **Whole Live Set** and **Save as new** persist the map, Scene does not (the map is not a scene field: `nothing_to_write` when it is the only edit). Power off loses an unwritten edit like any other.
- **GLOBAL_DEFAULT = a settings edit.** Written immediately to `<data>/setlists/assign_default.pb` through the `SetlistStore` atomic writer (temp file, fsync, rename, directory fsync; single writer rules as for the library); no Write is needed, the current Live Set is not dirty, the plane's revision moves by one and a State is pushed. A failure is typed and nothing is partial: `STORAGE_FULL` (ENOSPC), `STORAGE_FAILED` (details `reason`), the in-memory default and the file stay as they were; a failed directory sync is a success with the file in place. **Existing Live Sets are never changed** by it: a new Live Set copies the default at creation (`CreateLiveSet`, Story 4.6), so one created before the edit keeps the old map and one created after gets the new one.
- **Encoder mode and selected part.** `SetEncoderMode{PART | ALL | ASSIGN}` and `SelectPart{part}` (INVALID_PART above the last part) push a reserved UMP on the control lane, in order with the other control events (`engine/core/README.md`, "ASSIGN-mode encoders"). The plane remembers what it commanded and publishes it next to what RT applied: `State.encoders` = `{mode, selected_part, rt_mode, rt_selected_part, assign (the sounding Live Set's map), assign_default_available / assign_default, steps_applied, steps_empty_slot, steps_unrouted, steps_rejected}`. A command that changes the commanded value moves the revision and pushes a State; repeating it does not. The mode is engine state, not persisted (a restart starts in PART). Encoder steps are not a ws.v1 command: the panel delivers them as UMPs on the host event queue (Story 3.10), the offline renderer submits them with `--encoder-at`.
- **Where the code is.** `Snapshot::assign` is filled by `LiveSetLoader::stage()` from the Live Set; `EditSession::do_assign()` edits it; `ControlPlane` handles the mode/part commands and fills `State.encoders`; `SetlistStore::set_default_assign()` is the default's single writer.
- **Tests.** `assign_map_tests` (set / clear / replace / duplicates, dirty summary and moving back, every validation row changing nothing, no Live Set and no data directory, scene recalls / timbre rebuild / Live Set switches, Write and a power cycle through a second rig on the same data root, Save as new, the default's immediate write and independence of existing and later Live Sets, storage full and a failed directory sync, routing end to end through the real render driver incl. the dirty summary of what the encoders moved, a part with no engine, non-assignable ids in the stores, four concurrent socket clients beside an audio thread), `engine_host_assign_smoke` (the real engine-host with `--data-dir`, `--no-audio`: dirty push, immediate default file, typed refusals, mode/part reaching RT through the Write's fence, restart persistence, a new Live Set copying the persisted default; macOS), core `assign_tests`, `assign_traffic_test` / `rtsan_assign_test`, offline golden `assign_*`. No test asserts a duration.

## Scene recall (Story 4.4, `velora_control`)

`velora/host/scene_controller.hpp`: `SceneController` (control thread only; it registers itself as the plane's `SceneHandler`) recalls the loaded Live Set's scenes as a **parameter-only snapshot swap**.

- **What a recall does.** It copies the currently published generation, applies `apply_scene()` (below), builds effect instances only for a part whose insert chain really changed (the same instances otherwise, so RT does not cross-fade), gives the copy a new `program_generation` and `scene_index`, and publishes it with the usual single atomic store (`can_publish()` first: nothing changes on refusal). It never calls the resolver or a `HeadProvider`, never touches a part's timbre, `timbre_ref`, engine type, state or `sample_bank` (the new generation shares the very same `shared_ptr`s: tests assert pointer equality, delete the library files and count head loads), and the tempo and ASSIGN map are not scene fields. The loader gives the controller the Live Set and the generation it built (`LoadScope::commit`); a snapshot carries `scene_source` (the load's token), so a controller only recalls scenes onto the generation of the Live Set it holds (a Live Set loaded without the controller answers `kNoLiveSet`).
- **What a scene covers (full snapshot, sparse storage).** For every part: zone (`low_key`/`high_key`), octave, transpose, keyboard on/off, volume, Main/Aux, the insert chain and bypass flags, send levels, the engine / envelope / EQ sound parameters (drawbars, ...); and the master list. A recall sets each covered field to the scene's value or, when the scene does not store it, to the **base Live Set's value** (the controller keeps a copy of the base generation's values, without banks or chains). So recalling scene 2 after scene 1 puts back what scene 1 overrode and scene 2 does not; a structural command issued between (for example `SetPartOutput`) is overwritten for the fields the scene covers.
- **Performance values (AD-2 `program_generation`).** The scene's performance parameters are the generation's `perf_init` values; the generation carries a new `Snapshot::program_generation` (from `ControlPlane::next_program_generation()`, never reused) and `perf_force` flags exactly the slots the scene stores. RT (`BlockRenderer::adopt_generation`) applies, once, every slot whose value differs from what it applied before (as for any generation) **and** every `perf_force` slot of a generation with a new program generation. Defined behaviour: a recall **overrides a live knob move of the parameters the scene stores**, even when the stored value equals the base value; it **does not override a parameter the scene does not store** (its value is the base value, which RT already applied), except that a parameter the previously recalled scene had overridden returns to its base value; **recalling the current scene again resets its stored performance values to the scene's**; later generations (any structural command) copy the same program generation, so nothing is re-applied until the next recall. Part volume, zone, octave, transpose, keyboard flag, output and inserts are structural fields of the generation, not live values. Loading a Live Set does not force anything (the 4.3 behaviour).
- **Sounding notes.** Zone, octave, transpose and keyboard on/off are consulted when a note starts (the `PartRouter` records pitch and engine per held key): held, pedal-sustained and releasing notes keep their part and pitch and release normally, only new notes follow the new states. Volume, output and the insert chain belong to the part's bus and apply to the part's sound as a whole through the mixer's existing ramps (volume/output: one block / 5 ms, a changed chain: a 5 ms cross-fade, instance state is not carried over), without a gap. Tests: the audio of a scripted held / sustained / releasing performance is sample-identical with and without a recall that changes nothing audible; a volume change has no step.
- **Stepping.** `next_scene()` / `previous_scene()` walk the scene order and stop at the last / first scene (no wrap): result `kAtLast` / `kAtFirst`, nothing published. After a Live Set load (no scene recalled, `current_scene() == -1`) next goes to scene 0 and previous answers `kAtFirst`. `recall_scene(index)` jumps to any scene (`kNoSuchScene` when `index >= scene_count`).
- **Results (closed).** `SceneResult`: `kOk`, `kAtFirst`, `kAtLast`, `kNoSuchScene`, `kNoLiveSet`, `kLoadInProgress` (a `LoadScope` is alive: the load runs on this thread, so only a re-entrant call can see it), `kBusy` (the snapshot ledger is full: 32 generations pinned by sounding notes; nothing changes), `kFxBudgetExceeded` (the scene's effects would raise the FX cost above the plane's budget; nothing changes), `kInternal`. Everything else changes nothing and does not move the revision.
- **FX reservation.** With a scene controller the loader reserves the voice pool's FX cost for the **most expensive scene** (or the base), so a scene is never refused later for lack of reserved cost; a Live Set whose worst scene has more effect instances than the arbiter can list is refused at load (`kArbiterRejected`).
- **Timbre cannot be changed by a scene.** The scene schema has no timbre or engine type; unknown fields in a scene (hand-encoded, from a newer writer) are preserved by the format and ignored by a recall; ids the schema forbids in a scene's parameter lists (`timbre_ref`, `part_output`, the insert parameters, tempo) are rejected at load (`kWrongClass` / `kWrongScope`), and `apply_scene` ignores them even for a Live Set that skipped validation.
- **ws.v1.** Additive: commands `RecallScene{index}`, `NextScene`, `PreviousScene` (reply `SceneReply{result OK|AT_FIRST|AT_LAST, current_scene}` with `request_id` and the new revision; error codes `NO_SUCH_SCENE` (details `index`, `scene_count`), `NO_LIVE_SET`, and the existing `BUSY` / `FX_BUDGET_EXCEEDED`); `State` gains `live_set_loaded`, `current_scene` (-1 = none) and `scene_count`, `PerformanceValues` gains `current_scene`. A published recall is pushed to subscribers like any generation. Concurrent clients are serialized by the control thread (a test runs 4 clients x 60 recalls: every revision is distinct and contiguous). `engine-host --live-set` creates the controller.
- **Offline.** `velora-offline-render --live-set ... --scene-at SECONDS:INDEX` (repeatable), see `tools/offline-render/README.md`.
- Tests: `scene_controller_tests` (every Given/When/Then and matrix row: parameter-only swap with no head loaded and pointer-equal banks, performance values applied once / overridden / reset, held / sustained / releasing notes, zone change and note-off consistency, sample-identical audio, gap-free volume, stepping, missing scene, no Live Set, load in progress, a failed load keeping the old scenes, unknown fields and forbidden ids, inserts and the FX reservation and budget, a 1000-recall storm with held notes (`live_generations()` bounded, 1 at the end), the full ledger answering BUSY, ws.v1 over a real socket incl. 4 concurrent clients), `scene_rt_traffic_test` / `rtsan_scene_test` (3000 recalls in bursts of 1 to 12 beside dense keyboard traffic on 16 channels and the pedal, 8 scenes that move every covered field; the latter under RealtimeSanitizer, Docker/Linux clang only), offline goldens `scenes_*` in `tools/offline-render`.

## Control plane (Story 2.1, `velora_control`)

The only place protobuf is used next to the engine. A **control thread** is the sole writer of structural settings; clients (ui,
panel, Velora Studio) talk to it with `ws.v1` (`proto/ws_v1.proto`) over a Unix domain socket (mode 0600, default
`/tmp/velora-engine.sock`, `engine-host --socket PATH`).

- `control_plane` -- validates a command against the generated registry, builds a new immutable `core::Snapshot` generation,
  publishes it with one atomic store and replies `{request_id, revision}`. Any invalid command (unknown id, out of range, part > 7,
  performance param sent as structural or the reverse, too many insert slots, bad enum, empty command) returns a closed-enum
  `ErrorCode` and changes nothing: the revision does not move and nothing is published. `SetPerformanceParam` never creates a
  generation: it becomes one UMP stamped with host time on the control->RT lane (`RenderDriver`'s second SPSC queue, single producer
  = the control thread); the live value is read back from the lock-free last-value table (`GetPerformanceValues`).
  Commands: `SetInsertChain`, `SetSendLevels`, `SetPartOutput`, `SetMasterParams` (all-or-nothing), `SetTimbreRef`,
  `SetPerformanceParam`, `GetState`, `GetPerformanceValues`, `Subscribe`. The Ack of `SetPerformanceParam` means *queued*: RT can
  still drop the event when its queues overflow (counted: `param_events_rejected()`, `kEventOverflow`). Performance values travel
  as 32-bit normalised values (floats are quantised to ~2^-32 of the range; int/bool/enum are exact). `SetSendLevels` and
  `performance_init` apply on a generation change only where the value differs from the previous generation's initial value and
  never override a live value otherwise. `fill_state`/`fill_live_values` are control-thread only; `revision()`,
  `live_generations()`, `freed_generations()` are safe from any thread.
  Events at the same frame: the MIDI lane is submitted before the control lane, so at an identical timestamp the control
  value lands last (test `test_lane_tie_break_is_midi_first`). Generations are reclaimed here, per AD-23
  (`reclaim()`): freed once not current, not held by RT and not referenced by any sounding note.
- `control_server` -- (`set_tick()`: a hook run on every poll iteration, see "Seamless Live Set switching") one `poll()` thread: accept, length-prefixed frames (4-byte big-endian + protobuf, <= 65536 bytes),
  `Hello` handshake first (version must be 1, features are advertised: `params.v1`, `snapshots.v1`, `subscribe.v1`), commands
  serialized through the plane (concurrent clients get strictly increasing revisions, no lost update), `State` pushed to
  subscribers after each new generation. Framing violations (frame too large, wrong first message, unsupported version) get an
  error reply and the connection closes, as does an unparsable *first* frame (before Hello) and a client that has not handshaken
  within 5 s (`ControlServerLimits::handshake_timeout_ms`); beyond `max_clients` (64) connections are closed right after accept.
  After the handshake an unparsable frame or an invalid command gets an error reply and the connection survives. `Subscribe(true)`
  immediately pushes the current `State`. The socket is created 0600 (umask 0177), a path that is not a socket is never touched,
  and a stale socket is replaced only when connecting to it is refused. A reply above 64 KiB becomes an `INTERNAL` error. A client that falls 4 MiB behind is dropped. A stale socket file is replaced, a live listener is never stolen.
- **Effect instances and the FX budget (Story 2.7).** A `SetInsertChain` (or a dev-config part) makes the control thread build the part's `core::FxChain` (new, prepared effect instances
  from `core::make_effect()`; no plugin loading) and publish it with the generation; a command that does not change the chain (same types, bypass flags and params, or any other command) keeps the
  same instances, so RT only cross-fades when the chain really changed. `set_fx_budget(units)` (default `core::kMaxFxCost`) bounds `core::fx_cost_units()` of the resulting snapshot (insert effects,
  sends, master): a command that raises the cost above it returns `ERROR_CODE_FX_BUDGET_EXCEEDED` (details `fx_cost`, `fx_budget`), nothing is published and the instances built for it are freed on the spot; the same
  check refuses a dev configuration that does not fit. `fx_cost()` is the current generation's cost. `engine-host` reserves the arbiter with this budget FIRST
  (`LiveSetConfig::fx_cost = plane.fx_budget()`), so voices cannot eat into it. It is the flat budget, not `fill_fx_costs()` of the initial snapshot, because the arbiter reservation is static for the run while commands may raise the FX cost up to the budget. The dev configuration now sounds: part 0's reverb send (0.25) feeds the real reverb since Story 2.10 (default hall, 2 s, return level 1) and its delay sends feed the real delay since Story 2.11 (350 ms, feedback 0.35, return level 1, tempo sync off, tempo 120 bpm) and part 2 is on the Aux bus, which no adapter plays yet; the single-output `render_block` folds Aux into Main, so it is audible in `engine-host`.
  `RenderDriver::render_block_buses()` gives both buses.
- `dev_config` + `dev/engine-dev.json` -- the first generation until Live Sets exist (Epic 4): the JSON mapping of the `ws.v1`
  `State` message (parts 0-7: `timbreRef`, `inserts`, `sendReverb`/`sendDelay`, `output`; `master`; `performanceInit`). It is
  validated like a command and published as generation 1 **before audio runs**; an invalid file (unknown field, bad enum, out of range,
  duplicate part) makes `engine-host` print a clear error and exit 1. `engine-host --config PATH` selects another file.
- `midi_ingest` also turns MIDI CCs the registry maps (drawbars CC 70-78, ...) into performance parameter UMPs (channel = part);
  CC 64 (sustain) is forwarded unchanged to the renderer's pedal handling. Since Story 5.2 every other CC is forwarded as the MIDI 2.0
  control change itself (`MidiIngestCounters::controllers`): the block loop delivers it to the sample engine's per-part controller state (CC
  crossfades; `engine/core/README.md`, "Keyswitches, CC crossfades and filters"); a controller no engine reads is counted there as an ignored
  event. `engine-host` declares extended sample voices (`SampleEngine::Config::extended_voices`: the voice cost budgets a filter and a crossfade).
- Tests: `control_tests` (a real UDS client for every row of the story's matrix: handshake, structural commands, every invalid
  command, performance path via ws.v1 and CC, held note across a swap, 8 concurrent clients, generation exhaustion, socket
  lifecycle), `control_rt_traffic_test` / `rtsan_control_test` (10,000 parameter changes + 100 swaps beside a rendering RT thread;
  the latter under RealtimeSanitizer, Docker/Linux clang only).
- Requires `protoc` + libprotobuf (`brew install protobuf`; `protobuf-compiler libprotobuf-dev`). The library links Homebrew's
  abseil next to formatlib's vendored abseil only in the `engine-host` binary; the two use different inline namespaces.

## Library API client (Story 4.11)

`LibraryClient` (`velora/host/library_client.hpp`, target `velora_library_client`: the generated Library API code, protobuf and threads only) tells the `librarian` service which Live Set
became active and whether the engine is performing, so the librarian can keep Recent (AD-9: only the librarian writes the catalog). `report_active(id)` and `set_playing(bool)` never
block the caller: they push into a bounded queue (default 64; when full the OLDEST `report_active` is dropped and counted in `dropped()`, a `set_playing` only when nothing else is
queued) and a worker thread connects to the service's Unix socket, handshakes, sends and discards the replies. When the service is absent or goes away the worker reconnects with
exponential backoff (50 ms doubling to 2 s); queued messages wait; the latest `set_playing` value is re-sent first after every reconnect. `engine-host --library-socket PATH` wires it
(default off, every existing smoke test is unchanged): the Live Set that sounds is reported from the control tick when it changes, and `set_playing(true)` follows MIDI notes, `false`
after `--library-playing-idle-ms` (default 3000) without one, and on exit (`set_playing(false)` then a bounded flush in `stop()`); a hidden `--test-inject-note-after-ms N` counts as a note for the smoke test. The client also re-sends the last reported Live Set after a reconnect when no newer report is queued, and never evicts the item it is sending. Nothing else in `LiveSetSwitcher` / `EditSession` is touched.

Story 5.6 grows `library_api.proto` additively (catalog, `ImportRequest` / `ImportProgress`, `ListLibraries` / `ListInstruments`; `librarian/README.md`). `LibraryClient` does not use the new messages: it sends the same
handshake and commands and discards replies, so it works unchanged against the extended service (the new handshake features and the extra server messages are ignored by it). The UI and Studio reach the import
API through the same Library API over the same socket (Epic 5 surfaces); nothing in the engine process writes the catalog or `/data/lib`.

## macOS only (`macos/`, built only when `APPLE`)

- `CoreAudioLineIn` (Story 2.7, `ports::LineInSource`): optional capture of the default CoreAudio input device as 48 kHz stereo float into a lock-free ring that the engine drains once per block; mixed into the
  master (Main) only, at `line_in_level` (default 0). `engine-host --line-in` opens it; without the flag nothing is opened (so macOS asks for microphone permission only on request). With no input device, no permission, or an input device whose rate is not 48 kHz (captured audio is never resampled)
  `engine-host` prints "line-in: unavailable (reason)" and starts with a silent line-in. A mono device is duplicated onto both channels; callbacks larger than the slice buffer are captured in chunks. Capture and playback run on different clocks: a short jitter buffer pads with silence on underrun and drops the oldest
  frames when it runs ahead (`underruns()`/`drops()`). Not covered by automated tests (needs an input device); the port and the mixing are (`routing_tests`, `offline_routing_tests`).

- `CoreAudioOutput`: HAL output AudioUnit at 48 kHz stereo float; requests a 64-frame device buffer and reports
  what the device granted. The engine always renders 64-frame blocks; leftover frames carry to the next callback.
  The block start time is the callback's `mHostTime` (when the first frame is heard) plus the frame position.
- `CoreMidiInput`: UMP input port (MIDI 2.0 protocol, falls back to 1.0), connects all sources; `rescan()` picks up new ones.
  Events are stamped with mach host time (-> ns) in the CoreMIDI callback.
- `engine-host`: dev app.

```
cmake -S . -B build && cmake --build build
build/engine/host/macos/engine-host                 # runs until q + Enter or Ctrl-C
build/engine/host/macos/engine-host --duration 2    # headless short run, prints stats and exits 0
build/engine/host/macos/engine-host --socket /tmp/e.sock --config engine/host/dev/engine-dev.json
# protected (factory) libraries, dev builds only (Story 6.5). my-dev.pub-list is YOUR list: the committed tools/keys/trust/dev.pub-list is empty by design, so write one line
# `dev content-manifest <key_id> <public key hex>` for the dev content-manifest key `tools/keys/velora_keys.py generate` made (see tools/keys/README.md):
build/engine/host/macos/engine-host --live-set X.liveset --library-root ROOT --trust-list my-dev.pub-list --dev-device-key ~/.velora-dev-keys/device.x25519.priv
```

Notes arriving from any MIDI source play the engine test tone. It exits non-zero with a message if there is no output
device or the device cannot run at 48 kHz (the engine never resamples).

## Factory Live Sets (Story 6.9: FR34, AR31, `velora_control`)

The factory library ships with Live Sets (organ presets, piano setups, ...) that carry **vendor-assigned program ids** and reference instruments only by `(library_id, instrument_key)` or by engine
parameters. `tools/factory-release` packs them into ONE signed file, `factory-live-sets.vfls`; on first boot the engine's control thread verifies it and imports the Live Sets through the single writer
(`LiveSetStore`). Code: `velora/host/factory_live_set.hpp` + `src/factory_live_set.cpp`; schema: `proto/factory_live_set.proto`; tests: `factory_live_set_tests` (container, tamper sweep, install rules) and, with the
real pipeline against installed protected libraries, `factory_release_test`.

**File layout** (all integers little-endian; anything after the payload is refused):

| offset | size | field |
|---|---|---|
| 0 | 4 | magic `VFLS` |
| 4 | 2 | `container_version` = 1 |
| 6 | 2 | reserved = 0 |
| 8 | 8 | signer key id (first 8 bytes of SHA-256 of the Ed25519 public key; the release root's content-manifest key) |
| 16 | 64 | Ed25519 signature (RFC 8032, deterministic) |
| 80 | 4 | payload length N (<= 4 MiB; the whole file is <= 84 + 4 MiB) |
| 84 | N | payload: the serialised `velora.liveset.v1.FactoryLiveSets` message (deterministic: no maps, fields in number order, no unknown fields) |

The signature covers `"velora/factory-live-sets/v1" 0x00 || signer key id (8) || payload length (4, LE) || payload`: the payload bytes exactly as stored (the verifier never re-serialises). Verification is the
strict Ed25519 of `formatlib` (`ed25519_verify_strict`), against the injected `format::TrustedKeys` (dev: a `tools/keys/trust/<root>.pub-list`; production: the keys built into the image); an unknown signer is
`untrusted_key` before any signature work. A trust-list line carries a **root**; `format::TrustedKey::root` keeps it, and when it is not empty the payload's `root` must equal it (`root_mismatch`): a dev key cannot vouch for a production release. A key built from bare bytes has no root and binds nothing. `FactoryLiveSets` = `format_version` (1), `release_name`, `release_version` (`MAJOR.MINOR.PATCH`), `root` (`dev` | `factory-test` | `production`) and `entries`
(`program_id`, a complete `LiveSet`). Rebuilding from the same inputs gives the same bytes.

**Identity and the factory mark.** A factory Live Set's `id` is derived from its program id alone: a UUIDv4-shaped value from `SHA-256("velora/factory-live-set-id/v1" 0x00 || program_id (4, BE))`
(`derive_live_set_id`), so a later release replaces the same file and a user copy never collides. `LiveSet.factory` (`FactoryInfo{program_id, release_version}`, an additive optional field 9; unset in every
user Live Set and in every existing golden) is the "factory / read-only" mark. **Read-only:** `WriteLiveSet` scope `WHOLE_LIVE_SET` / `SCENE` on a factory Live Set is refused with `WRITE_SCOPE_UNAVAILABLE`
(`details.reason = factory_read_only`), nothing is written and the edits stay in memory; `SAVE_AS_NEW` makes an ordinary copy (the mark is cleared). Deleting a factory Live Set is allowed and is remembered.

**First-boot install** (`install_factory_live_sets`, control thread only; every failure is a typed `FactoryStatus` and writes nothing, except `store`):
1. size, magic, versions, length; the signer must be trusted (`untrusted_key`); the signature must verify (`signature_invalid`); the payload must parse (`bad_container`);
2. payload rules (`bad_release`, `duplicate_program_id`, `invalid_live_set`): format 1, a release name, a semantic version, a known root, 1..256 entries, program ids > 0 and unique, every Live Set valid for the
   tier (`liveset::validate`), `id == derive_live_set_id(program_id)`, and `factory == {program_id, release_version}`;
3. every `(library_id, instrument_key)` of every part resolves through the injected `ReferenceResolver` (`resolver_of(LibraryResolver)` resolves verified protected bundles too); otherwise
   `unresolved_references` with one `MissingReference{program_id, part, library_id, instrument_key}` per miss and **nothing written**;
4. the state file `<live set dir>/factory-live-sets.state` (text: `release V`, `root R`, `program N` lines, unknown `key value` lines ignored; written with the store's atomic replace, after the Live Sets, also after a
   partial failure where it records the ids actually written). It is **per root**: a state of another root is not used (a fresh state; no file is deleted). A missing or damaged state is **rebuilt from the factory marks in
   the store** (the programs present; the highest mark is the downgrade floor). A release OLDER than the recorded one is `downgrade`; otherwise per program id: no file and not recorded = **imported**; no file but recorded = **the user deleted it, it is not brought back**; a file with the factory mark of that program = replaced
   when this release is newer, **left alone when equal** (idempotent); a file with the id but no mark = **never touched**, reported as a conflict; a file at a factory id that cannot be read or parsed = **repaired** (rewritten, counted as updated). A crash between the Live Sets and the state file is repaired by running
   the install again.

`engine-host --data-dir DIR --library-root DIR --trust-list FILE --factory-live-sets FILE` (dev builds, with the dev key provider) runs it before the Live Set directory is scanned and then releases the store; a refusal
is printed on stderr and the engine starts with the Live Sets it has, unless `--factory-live-sets-required` is given (then the process exits 1). The board's wiring (embedded trusted keys, the image's `factory-live-sets.vfls`) comes with the provisioning image; the API is the same.

## Protected libraries (Story 6.5, `velora_host` + `velora_host_protected` + `velora_host_dev_keys`)

The engine plays a PROTECTED (factory) library exactly like a user library: the same resident PCM, the same banks, the same voices. What differs is how the PCM is
obtained and how the key is handled. FR30, FR31 (load), FR32, AR19, AR20, NFR17.

**Where things live.** `velora_host` stays free of cipher code (the librarian links it): `secure_memory`, `damage_registry`, `trust_list`, the resolver's verification
of `bundle.vlrp` (it links `velora_format_verify`: the Ed25519 check and hashes, no decrypt). Everything that decrypts is in **`velora_host_protected`**
(`protected/`, links `velora_format_decrypt` and OpenSSL): `ProtectedHeadProvider` and `EdgeBlockReader`. The only code that reads a device key from a file is
**`velora_host_dev_keys`** (`dev_keys/`): `DevKeyProvider`, built only when `VELORA_DEV_KEY_PROVIDER` is ON. **The option defaults to ON only for a plain development configuration**
(a single-config generator with an empty or `Debug` `CMAKE_BUILD_TYPE` and no `VELORA_PRODUCTION`); every other configuration (Release, MinSizeRel, RelWithDebInfo, a custom type,
a multi-config generator) defaults to OFF and needs an explicit `-DVELORA_DEV_KEY_PROVIDER=ON`, and Release / MinSizeRel / RelWithDebInfo / `VELORA_PRODUCTION` refuse it (message
"the dev key provider (a developer's device key ...) must not be built into a Release ..."). The librarian's dev trust variant has the same refusal list. ctest proves it:
`dev_key_provider_refused_in_production`, `dev_key_provider_refused_in_relwithdebinfo`, `dev_key_provider_default_off_in_release`, and `dev_key_provider_absent_when_off`, which builds
`velora-offline-render` (and `engine-host` on macOS) with the provider OFF and scans them (`tools/ci/check_no_dev_keys.py`: symbols and the option / key-file names) -- the option
names are compiled out of such a binary -- with the dev build scanned as the negative control. `docker-check.sh` configures with the option ON explicitly.
`tools/ci/check_core_deps.py` keeps `engine/core` and `engine/ports` free of OpenSSL; `check_format_no_decrypt.py` keeps proving the librarian binaries hold no cipher.

**Key-provider port** (`engine/ports/include/velora/ports/key_provider.hpp`): `KeyProvider::unwrap_content_key(library_id, wrapped_blob) -> KeyResult`; the result is a
`shared_ptr<const ContentKeyHandle>` that owns the key memory. `SecureKeyHandle` (`secure_memory.hpp`) is the host's handle: one anonymous page of its own, locked
(`mlock`; if the lock fails the key is refused with `memory_lock_failed`, never kept in swappable memory), excluded from core dumps (`madvise(MADV_DONTDUMP)` on
Linux; where `madvise` fails the key is refused too), the key written into it in place by the provider (no other copy; the unwrap temporaries -- shared secret and
wrapping key -- sit in the free part of the same page, so ONE locked page holds everything secret about an unwrap), and wiped (`explicit_bzero` / `memset_s`, not optimised away) when the last reference is
released, before the page is unlocked and unmapped. `PR_SET_DUMPABLE` is process-wide (it also blocks ptrace and `/proc/<pid>/mem` for the whole engine), so it is not
used; the host calls `disable_core_dumps()` once at start instead (`RLIMIT_CORE` 0, soft and hard: `engine-host` and `velora-offline-render` do it before the first
key exists), which holds on macOS too, where there is no per-region exclusion. OpenSSL copies key material into its own contexts for the duration of one block
or one unwrap and cleanses them when it frees them; the engine itself keeps no copy. **RLIMIT_MEMLOCK:** every live content key holds one page (4 KiB; 16 KiB on some boards) and the dev provider's device key one more, so a host that plays N protected
instruments at once needs about (N + 2) pages locked; Docker's default `ulimit -l` is 64 KiB, macOS gives unprivileged processes 64 KiB or unlimited depending on the release.
`memlock_budget_bytes()` reads the limit and `engine-host` checks it before the first key exists (refuses below 4 pages, warns below 64). A test hook (`SecureKeyHandle::Options::on_wipe`) reports the release AFTER the
wipe and before the unmap, with a pointer to the very memory the key lived in, so tests observe the zeros without touching freed memory.

**`DevKeyProvider`** (`velora/host/dev_key_provider.hpp`) implements `wrapped_key_v1` of `tools/keys/KEY-HIERARCHY.md` section 6 exactly: magic, algorithm, length and
recipient key id are checked first; `shared = X25519(device_private, ephemeral_public)` (all-zero refused); `HKDF-SHA256(IKM = shared, salt = ephemeral || device_public,
info = "velora/wrapped_key_v1/" || library_id)`; AES-256-GCM with AAD `blob[0:45] || library_id`. The device private key comes from an injected PATH (a
`device.x25519.priv`, 32 raw bytes, `tools/keys/velora_keys.py generate`), is held in a `SecureKeyHandle` and is never embedded or defaulted. The library id must be the canonical lower-case UUID text (`invalid_argument` otherwise; `Options::require_uuid_library_id` switches it off for the free-form pinned vector). The
shared secret and the wrapping key live in the free part of the content key's own locked page and are wiped on every path. Refusals are `KeyStatus` values (`malformed_blob`, `wrong_device`, `unwrap_failed`: another
library, a modified blob, a forged ephemeral key, a low-order key; `invalid_argument`, `memory_lock_failed`) and carry no key material. The tests pin both vectors of the
hierarchy document, flip every one of the 840 bits of a blob (each is refused, with the refusal class of its field), and check wrong library, wrong device and lock failure.

**Resolution.** `LibraryResolver` finds `<root>/lib/<library_id>/<bundle_id>/bundle.vlrp` (+ `wrapped-key.bin`), exactly as the librarian installs it, by the same exact paths
and only when `bundle.vlb` does not exist (an unprotected library costs exactly the ops it always did; a protected one adds one `open`), and VERIFIES it before it hands
out the instrument: header, manifest and index hashes, the signer against the **injected trusted keys** (`set_protected_trust(shared_ptr<const TrustedKeys>)`; without them
`kBundleError` / `untrusted_key`: nothing is opened on trust), the Ed25519 signature, the hash-list root, and the identity (the bundle's library id and bundle id must be the
ones its path claims). `ResolveResult` gains `protected_view`, `bundle_dir`, `library_id`, `is_protected()`. `load_trust_list_file()` reads a `tools/keys/trust/<root>.pub-list`;
the production image will pass its embedded set (Story 6.9 onwards) the same way. **Failures are typed and refuse the load.** A protected library that fails verification (signature, untrusted signer, hash list, damaged header / manifest / index) makes
`LiveSetLoader` refuse the Live Set (`kInstrumentLoadFailed`, `failed_part`, `load_status` = `signature_invalid` / `untrusted_key`, `LiveSetLoadResult::bundle_error` = the exact
formatlib cause, `PartLoadReport::resolve_error`), the previous generation keeps playing; a host with NO trusted keys configured resolves it to `kProtectedUnsupported` and the
part is silent with "Missing library" (it plays no protected library at all); plain absence and I/O trouble stay "Missing library" as for any library. **Downgrade:** an
unprotected `bundle.vlb` standing beside `bundle.vlrp` or `wrapped-key.bin` in a bundle directory is refused (`kProtectedDowngrade`, `protected_downgrade`, also a load refusal)
before it is read -- the resolver does two `lstat`s for it, so the resolver's constant is 10 ops (4 `lstat`, `readlink`, `open`, 3 `pread`, `close`), asserted by ctest.

**Loading (head loader).** `ProtectedHeadProvider` is a `HeadProvider` (it passes unprotected instruments to the RAM provider unchanged). For a protected one it reads
`wrapped-key.bin`, obtains the content key through the port, opens a `ProtectedBundleReader` over the verified view **borrowing** the key (`open_view`; the reader's key
check refuses a key that is not the bundle's: `wrong_content_key`), and makes the instrument resident through the ONE loader (`load_instrument_by_index(InstrumentSource&)`):
every ciphertext block is hash-checked, AES-CTR decrypted and decoded on the loading thread, and the audio thread later reads decoded float PCM from RAM. The estimate for
the head budget comes from the index alone, as for any library. Typed refusals (`LoadStatus`, spelled `to_string`): `content_integrity` (a block fails its hash or does
not decode; the load is refused at the first bad block and nothing partial stays resident), `wrong_content_key`, `signature_invalid` / `untrusted_key` (also
`load_status_from(format::Error)` for callers that open a bundle themselves), `key_unavailable` (the provider refused: wrong device, another library, a modified or missing
blob; `last_key_status()` says which), `protected_unsupported` (a host with the plain RAM provider meets a protected instrument). They surface as
`LiveSetLoadStatus::kInstrumentLoadFailed` with `load_status` set and the cause in `detail`; the previous generation keeps playing.

**The key belongs to the generation (AD-23).** The reader (which holds the key handle) is hung on the `BundleInstrument` (`attach_context`), and the instrument is what every
generation that plays it shares (`SampleBank::owner`). So the control thread obtains the key when the generation is prepared, the generation keeps it for as long as any
voice can read from it, and `reclaim()` frees the generation on the control thread after its last voice ended, which destroys the instrument, the reader and the handle:
the key page is wiped then (test: the wipe observer fires exactly once, after the note ended and `reclaim()` ran, with all-zero memory, and not before).

**I/O edge threads.** `EdgeBlockReader` does the same decrypt + decode block by block on a thread of its own (`read_block_pcm`: how the streamer of Story 1.17 fills its
buffers; `check_block`, `scrub`: re-verify a resident instrument against the signed index). A block that fails its integrity check is marked damaged in the instrument's
damage map (`BundleInstrument::mark_block_damaged`, one atomic byte per block, `ports::SamplePcm::damaged_blocks`), reported to the `DamageRegistry` and the error returned;
an I/O error says nothing about the block: it marks nothing, but it is **counted and shown** (`ScrubResult::io_errors`, `DamageRegistry::report_io_error`,
`State.content.io_errors`), not dropped. Only the **first** detection of a block (`mark_block_damaged` returns true on the 0 -> 1 transition) is reported, so repeated scrub passes over
the same damage leave every counter stable and cause exactly one State push; a library that loads cleanly again (reload, reinstall) is cleared (`DamageRegistry::clear_library`, another push).
The reader holds its instrument WEAKLY and takes a reference for one block at a time: a scrub never keeps a generation, and with it the content key, alive. When the generation is
freed (even from another thread while a scrub runs) the key is wiped at once and the scrub ends with `generation_gone` (test `test_reclaim_during_scrub`). Every block's decoded int32
copy is wiped on every return path. `engine-host --scrub-interval-ms N` (default 30000) runs a scrub of every resident protected instrument on such a thread (over
`ProtectedHeadProvider::live_weak()`).

**Streaming deviation (read this).** Streaming itself -- Stories 1.16/1.17, the head loader and the NVMe streamer -- is board work that does not exist yet. Today instruments are fully
resident, so the AES-CTR decrypt and hash check happen at load, on the loading thread. What this story therefore delivers for "a block whose hash fails *during streaming*" is the
mechanism, driven by the scrub as a substitute: the damage map, the RT fade and the `content_integrity` count, the report and the State push, and `EdgeBlockReader::read_block_pcm`
(the decrypt-and-decode call a streamer will make per block). NOT covered, and for Story 1.17 to add: detection triggered by a *read* of the block the voice needs (a streamer finding
the bad block as it refills its ring buffer), and failure of a *refill* (the streamer's own error path). A block damaged on disk after the load is found at the next scrub, not at
the moment the voice reads it; until then the resident, already verified PCM keeps playing.

**Integrity at run time.** The audio thread never hashes, decrypts or waits: each voice over a protected sample reads a few relaxed bytes per frame. It fades to silence over
`core::kIntegrityFadeFrames` (64) output frames BEFORE it reaches a damaged block, is silent through it, fades back in after it; a voice that starts, or whose block is flagged late, inside
the look-ahead window is capped at `distance / look-ahead` of full gain (so it never plays a damaged block at full gain; the cap can force one step instead of a ramp), and a voice that starts inside one starts
silent; each entry counts one `content_integrity` event (`SampleEngine::content_integrity_events()`, published once per block to `LastValueTable`). The control plane shows
it in the additive `State.content` (`ContentStatus`: `content_integrity`, `damaged_library_count`, `damaged_library_ids`, `damage_reports`, `io_errors`; `ControlPlane::set_damage_registry`
bumps the revision on every visible change and the control tick pushes the State to subscribers). A damaged library stays reported until it is reloaded or the engine restarts.

  Latency and xrun budgets are accepted only on the dev board.
- ctest needs no audio device or MIDI keyboard. `coremidi_virtual_test` uses CoreMIDI virtual sources and exits 77
  (reported as skipped) when CoreMIDI is unavailable.
