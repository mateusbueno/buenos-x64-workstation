# engine/ports

Role: port interfaces through which `engine/core` reaches the outside world; implemented by adapters in `engine/host/`.

Dependency rule: header-only interfaces that may depend only on the C++ standard library (and other ports).

Sample-source port (Story 1.15, `velora/ports/sample_source.hpp`): an instrument's region table (`SampleRegionDesc`) and fully RAM-resident float PCM, planar per channel (`SamplePcm`), as plain structs and spans. `SampleEngine` in `engine/core` consumes it; `engine/host` (`sample_bundle_loader`) fills it from a formatlib bundle. The source owns the memory and must outlive the engine's use of it.

Line-in port (Story 2.7, `velora/ports/line_in_source.hpp`): `LineInSource::read_block(left, right, frames)` fills the next 64-frame stereo block of an external input; the engine mixes it into the master only, at the `line_in_level` parameter. `SilentLineIn` is the default (dev board and Linux until Epic 3). Real-time safe: adapters that capture on another thread hand over through their own lock-free buffer and return silence for what they do not have.

Block-damage map (Story 6.5, `SamplePcm::damaged_blocks`): a *protected* sample may carry one atomic byte per 4096-frame block (`damaged_block_frames`, `damaged_block_count`), set by non-real-time threads (the host's I/O edge threads) that found the block failing its hash check, and only *read* by the audio thread: a voice fades to silence for a damaged block and counts a `content_integrity` event (`engine/core/README.md`, "Content integrity"). `nullptr` (every unprotected sample) means no map and the Story 1.15 render, bit for bit.

Key-provider port (Story 6.5, `velora/ports/key_provider.hpp`; FR30, AR19, AR32): `KeyProvider::unwrap_content_key(library_id, wrapped_blob) -> KeyResult` (a closed `KeyStatus` and a `shared_ptr<const ContentKeyHandle>`). The handle owns the 32-byte content key memory; the host's implementation locks it in RAM, excludes it from core dumps and wipes it when the last reference is released (`engine/host/README.md`, "Protected libraries"), and the engine attaches the handle to the generation that uses the library, so the key lives and dies with that generation (AD-23). The port carries no cryptography and no formatlib type (standard library only, like the rest of this directory). Implementations: `engine/host/dev_keys` on the Mac (X25519 + HKDF-SHA256 + AES-256-GCM, `wrapped_key_v1` of `tools/keys/KEY-HIERARCHY.md`), the OP-TEE trusted application on the board (Story 6.6). `KeyStatus`: `ok`, `invalid_argument`, `malformed_blob`, `wrong_device`, `unwrap_failed`, `unavailable`, `memory_lock_failed`, `internal`; none carries key material.
