# proto

Role: the single owner of parameter ids and of the `ws.v1` wire schema (Story 2.1).

- `params.json` -- the parameter registry definition (JSON, parsed with the Python 3 standard library: no new dependency).
  Every parameter has a stable numeric `id` (1..16383, 14 bits: a UMP assignable controller carries it as bank + index),
  a `name`, a `class` (`structural` | `performance`, mandatory), a `type` (`int` | `uint` | `float` | `bool` | `enum`),
  a `scope` (`part` = one value per part (8), `master`, `insert` = per insert slot), `min`/`max`/`default`, a `unit` and an optional
  MIDI `cc` (performance + part scope only). Enum parameters name an entry of `enums`; their range is `0..count-1` and the default
  is a value name. Declared here only what Epic 2 needs: tonewheel organ (drawbars 1-9, percussion, vibrato/chorus, key click,
  leakage), rotary speed, inserts (type, bypass, 5 params; the 5th is the compressor makeup, Story 2.8), send levels, master EQ/compressor, master level, line-in level, per-part output, timbre reference.
- **Ids are never reused.** To retire a parameter delete it from `params` and add its id to `reserved`; the generator fails if a
  parameter ever takes a reserved id.
- `gen_params.py` -- deterministic generator (same input, same bytes). Emits `--core` (C++ header for `engine/core`, numeric tables,
  no names), `--host` (C++ header for `engine/host`, names and enum value names) and `--proto` (`ws_v1_params.proto`, the `ws.v1`
  `ParamId` enum and one enum per registry enum). It fails, naming the problem, on: duplicate id, duplicate name, missing or unknown
  class, reserved id reuse, ids out of 1..16383, bad type/scope, range/default inconsistency, unknown enum, duplicate or reserved CC.
  Nothing is written when validation fails.
- `params.cmake` -- `velora_params_output(core|host|proto <var>)` registers the generation as a build step of the calling target,
  so an invalid `params.json` fails the build. Generated files live in `build/generated/` and are not committed.
- `ws_v1.proto` -- the `ws.v1` schema (package `ws.v1`, `PascalCase` messages, `snake_case` fields; it only grows by addition,
  numbers are never reused). Framing: 4-byte big-endian length + protobuf, largest frame 65536 bytes. First message on every
  connection is `Hello` (version + features); errors are `{code, message, details}` with `code` from the closed `ErrorCode` enum.
- `live_set.proto` -- the persisted Live Set (Story 4.2; package `velora.liveset.v1`, same naming conventions, imports `ws_v1.proto`
  for `InsertSlot`/`PartOutput`). Versioned by `format_version`; grows only by addition; see `engine/host/README.md` for the semantics.
- `factory_live_set.proto` -- the payload of the signed factory Live Set file (Story 6.9; package `velora.liveset.v1`, imports `live_set.proto`): `FactoryLiveSets{format_version, release_name, release_version, root, entries{program_id, live_set}}`. The container (magic, key id, Ed25519 signature) and the install rules are in `engine/host/README.md` ("Factory Live Sets"). Story 6.9 also adds, additively, `LiveSet.factory` (`FactoryInfo`, field 9) to `live_set.proto`: the factory / read-only mark, unset in every user Live Set.
- `setlist.proto` -- the persisted setlists, setlist tags and default ASSIGN map (Story 4.6; package `velora.setlist.v1`, same conventions as `live_set.proto`: grows only by addition, N / N-1 readers, unknown fields preserved). Layout and rules: `engine/host/README.md` ("Setlists, setlist tags and Live Set stepping").
- `category.proto` -- the 17 instrument categories plus the explicit `CATEGORY_NONE` sentinel (Story 5.5; package `velora.library.v1`; ids 1..17 stable, grow by addition only,
  none is never stored on an instrument). Hand maintained next to its C++ twin `formatlib/include/velora/format/category.hpp`; see `formatlib/README.md` ("Categories and locale catalog").
- `library_api.proto` -- the Library API of the `librarian` service (Story 4.11; package `ws.v1`, same conventions as `ws_v1.proto`). Messages whose name exists in `ws_v1.proto` carry a `Library` prefix (`LibraryHello`, `LibraryHelloAck`, `LibraryError`, `LibrarySubscribe`, `LibraryState`, `LibraryAck`) so both files link into one program; the envelope is `LibraryClientMessage` / `LibraryServerMessage`. Built as `velora_library_api` (protobuf only). Semantics: `librarian/README.md`. Story 5.6 adds, additively, the libraries catalog and import API: `ImportRequest` / `ImportAccepted` / `ImportProgress` (push) / `CancelImport` / `ImportStatusRequest`, `ListLibraries` / `LibraryList`, `ListInstruments` / `InstrumentList`, the enums `ImportState`, `ImportItemStatus`, `ImportReason`, and the error codes `CATEGORY_REQUIRED` (10), `INVALID_SOURCE` (11), `QUEUE_FULL` (12), `UNKNOWN_JOB` (13), `UNKNOWN_LIBRARY` (14), `SHUTTING_DOWN` (15); `category` in `ImportItem` / `ImportInstrumentOverride` is `optional` so that a missing category (reason `missing`) and an explicit 0 (reason `none`) are told apart; the handshake features gain `import.v1` and `catalog.v2`. Category fields are the numeric ids of `category.proto` (1..17; 0 is never accepted for an import).
- `tests/test_gen_params.py` -- ctest `params_generator_tests`: runs the generator on bad definitions and checks determinism.

## Parameter classes

| class | who owns the value | how it changes | path to RT |
|---|---|---|---|
| structural | the control thread (snapshot generation) | `ws.v1` structural commands | immutable `Snapshot`, one atomic pointer swap |
| performance | RT (last-value table) | `ws.v1` `SetPerformanceParam` or MIDI CC | one timestamped UMP |

Performance UMP mapping (`engine/core/include/velora/core/param_events.hpp`): MIDI 2.0 assignable controller (message type 4,
status 0x3), group 0, channel = part, bank = `id >> 7`, index = `id & 0x7F`, 32-bit value normalised over the parameter range.
MIDI CC numbers map through `cc` (drawbars 1-9 = CC 70-78, rotary speed 79 (stop/slow/fast: the 7-bit range splits as 0-31 stop, 32-95 slow, 96-127 fast), rotary on/off 89, percussion 80, vibrato/chorus 81, key click 82, leakage 83, percussion harmonic/decay/volume 84/85/86 (value < 64 = first enum entry), vibrato/chorus type 87 (the 32-bit range is split evenly over v1..c3: index = round(value/127 * 5) for a 7-bit CC),
reverb send 91, delay send 94); the CC's channel is the part (0..7).
`line_in_level` (id 800) is the one performance parameter with master scope: its UMP uses channel 0 and it has no CC. `master_level` (id 520, dB) is structural.
`master_eq_bypass` (504) and `master_comp_bypass` (515) are structural flags (Story 2.8). Story 2.10 adds `reverb_type` (530, enum room/hall/plate), `reverb_time` (531, s) and `reverb_level` (532) as structural master parameters (`SetMasterParams`), and `send_reverb_master` (801, performance, master scope, 0..1, default 1: the REV master send level that scales every part's reverb send; UMP channel 0, no CC). Story 2.11 adds the delay: `delay_time` (540, ms 1..2000), `delay_sync` (541, flag), `delay_note` (542, enum quarter/eighth/sixteenth, dotted and triplet variants), `delay_feedback` (543, 0..0.95: strictly below unity), `delay_level` (544), `delay_damping` (545) and `delay_pingpong` (546) as structural master parameters (`SetMasterParams`), and `tempo_bpm` (802, performance, master scope, 20..300 bpm, default 120: the RT plane's single tempo value, UMP channel 0, no CC; the internal tempo is the only source until Epic 7's clock follower). The DELAY encoder function binds to the unchanged per-part `send_delay_level` (401, CC 94). The compressors' gain reduction is engine state, not a parameter: `GetPerformanceValues` returns it in `PerformanceValues.gain_reductions`.
`ERROR_CODE_NO_SUCH_SCENE` (16) and `ERROR_CODE_NO_LIVE_SET` (17, Story 4.4): `RecallScene` for a scene the loaded Live Set does not have, and any scene command with no Live Set loaded (`NextScene` / `PreviousScene` at the ends are not errors: `SceneReply` carries `AT_LAST` / `AT_FIRST`). Story 4.4 also adds the commands `RecallScene`, `NextScene`, `PreviousScene`, the reply `SceneReply` and the read fields `State.live_set_loaded`, `State.current_scene`, `State.scene_count`, `PerformanceValues.current_scene` (all additive).

`ERROR_CODE_FX_BUDGET_EXCEEDED` (15, Story 2.7): a structural command whose insert chains, sends and master would cost more than the FX budget reserved by the arbiter.

## Key contact events (`contact_k`, Story 2.5)

Not a registry parameter: the multi-contact keybed's per-note vendor controller, defined in `engine/core/include/velora/core/contact_events.hpp`
and documented in `engine/core/ORGAN.md`. MIDI 2.0 assignable **per-note** controller (message type 4, status 0x1), group 0:
`word0 = 4<<28 | 1<<20 | channel<<16 | note<<8 | k`, `word1 = 0xFFFFFFFF` (contact k closed) or `0` (open); a value of 0x80000000 and above reads as
closed. `k` is the contact index, 1..3 (1..2 on a two-contact keybed); the wire accepts 1..8, other per-note controller indices are not `contact_k` and are ignored; `channel` is the part, `note` 0..127. One event per contact
transition, timestamped like every other UMP; contact 1 closes first on the way down and opens last on the way up, and a Note On
follows the closures (Note On/Off-only sources simply send no contact events). This is the format the Epic 3 keybed reader emits; it
is distinct from the performance-parameter events above (status 0x3, not per-note).

## sysd config (Foundation: sysd config service)

- `ws_v1.proto` carries the system-config messages (additive): enums `ClockSource`, `VelocityCurve`, `PedalPolarity`, `BootIntoMode`; messages `PedalCalibration`,
  `BootIntoConfig`, `Config`, the field-wise `PedalPatch` / `BootIntoPatch` and `ConfigPatch` (only the scalar fields present change; a patch never clears fields it does not name; the merged result is validated), `GetConfig` (ClientMessage 55), `SetConfig` (56), `SubscribeConfig` (57), `ConfigReply` (ServerMessage 25) and
  `ERROR_CODE_INVALID_CONFIG = 41`. They are spoken by `velora-sysd` only; the engine's control server answers them with `ERROR_CODE_INVALID_COMMAND`.
- `sysd_config.proto` is the persisted `SysdConfig` (`schema_version` = 1, `revision`, the ws.v1 `Config`), written only by sysd to `<data>/config/sysd_config.pb`.
  Same rules as the other persisted forms: addition only, numbers never reused (`reserved` on retirement), readers accept N and N-1, unknown fields are kept.
- Both are built with the engine/host protobuf code (`engine/host/CMakeLists.txt`). Details, validation rules and how a story adds a field: `sysd/README.md`.
