# Sample-engine null-test suite (Story 1.15)

Synthetic SFZ library + MIDI files + **committed sfizz 1.2.3 renders**, so `ctest` compares the engine against the oracle without sfizz
installed. Everything but the goldens is generated by `generate_suite.py` (committed output, deterministic; samples are 16-bit WAVs of a
few KB). The goldens (`golden/<case>.wav`) are the untouched 16-bit output of `sfizz_render` (48 kHz, 64-frame blocks, quality 2, or 1
for the linear case), made by `regenerate_goldens.sh` through `tools/oracle` (`../../../oracle/README.md`). `cases.txt` lists the cases;
CMake registers one ctest per line (`sample_null_<case>`), the driver is `../sample_suite_test.cpp`.

## How a case runs

1. `librarian import sfz/<case>.sfz` into a scratch root (the real importer, so the SFZ subset and the bundle path are exercised).
2. `velora-offline-render --engine sample --bundle ... --instrument <case>.sfz --gain-db -7.35 --oracle-block-frames 64 --tail-seconds 1`.
3. `velora-null-test --case golden/<case>.case --candidate ...`: reads the sfizz 16-bit file, undoes its float->s16 conversion
   (`reference_decode=sfizz-s16`), tries **no alignment offset** (`max_offset_frames=0`, a timing error cannot hide), and fails if the
   residual RMS relative to the reference RMS is above the tolerance or if signal outside the compared range (a tail in one file only)
   exceeds it (`check_excess=1`).

## Results and tolerances

Tolerance = the -60 dB proposal for every case; none had to be loosened. Residual = 10 log10(sum (ref - engine)^2 / sum ref^2) over both
channels, measured on macOS arm64 (Apple clang 21, Release). The remaining ~ -68 dB is the sfizz *oracle's* own deviation, not an engine
difference (see "Residual floor"); `worst window` is the worst 100 ms window against the file's mean window energy.

| case | what it covers | residual | worst 100 ms | tolerance |
|------|----------------|---------:|-------------:|----------:|
| velocity_layers | 3 velocity layers, boundaries 40/41 and 80/81, vel 1 and 127, two off-centre keys | -67.9 dB | -61.5 dB | -60 dB |
| round_robin | `seq_length` 4 (positions cycle and wrap) and an independent 2-cycle on another key, interleaved | -68.0 dB | -65.6 dB | -60 dB |
| random_layers | `lorand/hirand` splits (2 and 3 ways) whose regions share a sample, so the render does not depend on either RNG | -67.9 dB | -66.0 dB | -60 dB |
| pitch_far | notes 12..96 from a centre of 60 (ratios 1/16 .. 8), `tune=37` + `transpose=-5`, a 44.1 kHz sample at three keys | -67.8 dB | -65.4 dB | -60 dB |
| pitch_far_linear | the same with linear interpolation (sfizz quality 1) | -67.8 dB | -65.0 dB | -60 dB |
| volume_pan | `volume` -6/+3.5/-20 dB, `pan` -100..100, mono and stereo samples, plain mono and plain stereo | -66.6 dB | -60.6 dB | -60 dB |
| offset | `offset` into the sample, pitched, and 1000 frames before its end | -67.8 dB | -65.4 dB | -60 dB |
| envelope | delay, attack, hold, decay, sustain, release, `ampeg_start`, a release below 6 ms, a long release re-triggered mid-release, a note off during the delay | -67.1 dB | -61.5 dB | -60 dB |
| loops | `loop_continuous` (explicit, pitched, whole-sample), `loop_sustain` (released out of the loop), `one_shot` (note off ignored), `no_loop`, a sample that ends on a non-zero value while held | -65.4 dB | -61.5 dB | -60 dB |
| release_trigger | release region on note off (not on note on); not fired when the attack voice is gone; fired while it is still fading; velocity layers + release round robin; note-on velocity used | -68.1 dB | -64.4 dB | -60 dB |
| poly_layers | layered regions on one key, a chord, re-triggers, the unspecified (default) release | -66.1 dB | -63.2 dB | -60 dB |

Negative tests prove the harness can fail: a 1 dB gain error (`sample_null_neg_gain`) and the wrong interpolation kernel on the
`pitch_far` case (`sample_null_neg_interp`) must both be rejected on residual.

### Residual floor

- **Pan table rounding.** sfizz's NEON pan path indexes its cosine table differently from its generic path (left index 2048, right
  2046 at centre against 2047 and 2047), so a centred voice differs by about 4e-4 between channels, which is -68 dB. The engine uses the
  generic rounding; the oracle on x86 would show a different (but equally small) offset.
- **16-bit oracle output.** The reference is quantized to 16 bit (-78..-83 dB for these signals) after being scaled by 32767.5.
- Together these explain the -65..-68 dB. No case is limited by interpolation, envelope curves or normalization once the three oracle
  artefacts below are accounted for; the margin to the -60 dB tolerance is 5..8 dB. Without the compensations below the same suite
  measures +8.8 dB (master volume and CC7) and about -20 dB (the stutter).

### Oracle artefacts the setup compensates for (none is an engine feature)

1. **Master volume and default controllers.** sfizz's master volume defaults to -7.35 dB (`Default::globalVolume`) and its default
   MIDI state is CC7 = 100 (applied squared as `amplitude`), CC10 centred, CC11 = 1. Every MIDI file starts with CC7 = 127 and its notes
   begin 4800 frames in (so sfizz's CC smoothing has settled); the engine runs with `--gain-db -7.35`.
2. **Block-boundary stutter.** sfizz 1.2.3 computes a voice's age as `min(age + block - trigger_delay, 0)`, which never leaves 0, so
   the "voice just started" rule (the first frame of a block does not advance the position) fires again at the first block boundary
   after the voice's start block: every voice repeats one sample position once, which shifts the rest of the note by one frame (-20 dB
   residual otherwise). `--oracle-block-frames 64` (`SampleEngine::Config::oracle_block_frames`, test only, off by default) reproduces
   it.
3. **float->s16 conversion** of `sfizz_render` (silence -> -1 LSB, scale 32767.5): decoded with `reference_decode=sfizz-s16`.

### Constraints the suite keeps so that sfizz behaves

- MIDI timing: 32000 PPQ at 120 bpm = 0.75 frame per tick. Each event is placed at a quarter-frame fraction, never on an exact frame
  boundary, so the oracle (which advances its MIDI clock in double arithmetic, one sample at a time) and our SMF reader (integer
  `floor`) cannot disagree by a frame through rounding. The alignment search is not used (`max_offset_frames=0`) and every case aligns.
- `loop_sustain` note offs sit on 64-frame block boundaries: sfizz tests "released" once per block, not per frame.
- No note on whose start offset plus `ampeg_delay` ends exactly on a block boundary (envelope note 62 starts 13 frames late for this):
  sfizz's ADSR then leaves `delay` at 0 instead of -1, loses the note off and the voice sustains forever (the oracle script caps the
  output size because of this).
- The note off of a voice in its `ampeg_delay` is on a block boundary: sfizz only drops the voice when the remaining delay at block start
  exceeds the event's in-block offset.
- `ampeg_release` is never written as an explicit 0 (the bundle cannot tell it from unspecified; sfizz treats the two differently, see
  `engine/core/README.md`).
- Random layers: the test cannot compare which region each engine's RNG picks, so paired regions carry identical audio; the draw
  distribution and reproducibility are unit tests (`engine/core/tests/sample_engine_test.cpp`).

## Story 5.2: keyswitches, CC crossfades and filters

One fixture instrument per feature (generated by `generate_suite.py`, goldens rendered by the sfizz 1.2.3 oracle with `regenerate_goldens.sh`,
committed like the others; the Story 1.15 files and goldens are untouched). The MIDI files now carry control changes (`write_midi(..., ccs,
setup)`): the controllers sit at quarter-frame ticks like the notes, and a case that moves a controller sets its start position at tick 0, after
CC7 = 127. Residuals measured on macOS arm64 (Apple clang 21), tolerance -60 dB for every case, none loosened:

| case | what it covers | residual | worst 100 ms | tolerance |
|------|----------------|---------:|-------------:|----------:|
| keyswitch_last | `sw_last` 36/37/38/39 declared out of order, `sw_default=36`, `sw_lokey=36 sw_hikey=39`; silent switch presses; key 39 is also a mapped region that sounds and switches; back to 36 | -67.9 dB | -63.6 dB | -60 dB |
| keyswitch_down_up | `sw_down=36` and `sw_up=36` regions on the same keys while key 36 is held / released, three times | -67.8 dB | -64.0 dB | -60 dB |
| keyswitch_previous | a region on key 62 that adds itself only after a note on key 60 (`sw_previous=60`) | -68.0 dB | -63.5 dB | -60 dB |
| xfade_power | two looped samples crossfaded on CC1 (`xfout_locc1/hicc1` 0..100 against `xfin` 30..127) over a full 1.5 s sweep up and back in whole steps; CC11 sweep on key 64; one region with `xfin` on CC1 and `xfout` on CC11; four large jumps of the wheel (100, 20, 127, 0) on an xfin 40..80 region; `xf_cccurve=power` | -62.6 dB | -59.7 dB | -60 dB |
| xfade_gain | the same with `xf_cccurve=gain` | -62.6 dB | -58.8 dB | -60 dB |
| filters | `lpf_1p` 800 Hz, `lpf_2p` 1500 Hz/6 dB, `hpf_1p` 2 kHz, `hpf_2p` 1.2 kHz/3 dB, `bpf_2p` 1 kHz/2 dB, a stereo `lpf_2p` 3 kHz/12 dB, the default type (only `cutoff=500`), cutoffs of 15 kHz, 300 Hz/20 dB and 18 kHz, an unfiltered neighbour; one bright 110 Hz sample with 40 harmonics and noise | -64.3 dB | -53.6 dB | -60 dB |

The crossfade cases have the lowest margin (2.6 dB): the remainder is the difference between sfizz's smoother (a 5 ms linear ramp restarted per
16-frame chunk of a block whose gain envelope ramps up to the event) and the engine's (a 5 ms ramp restarted at the event frame), added to the
oracle's own -68 dB floor; the worst 100 ms window sits on the wheel jumps. The engine's first crossfade smoother was a 15 ms one-pole (my first
reading of `Smoothers.h`, which has both): it measured -26 dB on these files; sfizz's `Smoother` is the LinearSmoother (`using Smoother =
LinearSmoother`), and with it the residual fell to the floor. Filters reach -64 dB with the double-precision port of the RBJ biquads and the
matched-pole one-poles.

`sample_null_neg_strip_<case>` imports the same SFZ with its Story 5.2 opcodes removed (`sw_*`, `xfin_*`, `xfout_*`, `xf_cccurve`, `fil_type`,
`cutoff`, `resonance`) and requires the null test to FAIL on residual: the keyswitch regions would all play at once, the crossfades would
sound at full level, the filters would be bypassed. The fixtures are the proof that each feature is audible and that the harness sees it.

What the oracle does that the engine does not (none of it a Story 5.2 feature, all of it kept out of the fixtures):

- **Default controllers.** sfizz connects CC7 (volume, squared), CC10 (pan) and CC11 (expression, squared) to every region unless the instrument
  itself uses that controller somewhere (`Synth.cpp`, "connect default controllers"). The engine keeps them in its controller state but does not
  apply them. The suite never moves them: `xfade_*` use CC11 in crossfades (so sfizz's default mapping is off for that instrument), and the real
  library probe `demo_features.mid` sweeps CC1 and CC2 only. A library that is played with a moving CC7/10/11 will differ from sfizz.
- **`sw_lokey`/`sw_hikey`.** sfizz ignores them; the engine uses them to name the keys that set the `sw_last` state (the SFZ specification). The
  fixtures declare every key of the range as some region's `sw_last`, where both agree.
- **Several keyswitch opcodes on one region.** sfizz toggles one flag; the engine ANDs the opcodes. The fixtures use one opcode per region.

## Story 13.4: velocity and amplitude model

One fixture instrument per opcode family, generated by `python3 generate_suite.py story134` (only these cases are written; no older file is touched),
goldens rendered by the sfizz 1.2.3 oracle with `regenerate_goldens.sh amp_veltrack amp_velcurve amp_gain ampeg_vel2 amp_keytrack`. The velocity
sweeps use whole MIDI velocities. Residuals measured on macOS arm64 (Apple clang 21). The -60 dB tolerance applies to the overall residual (the `residual` column) only; the worst 100 ms window is reported for information and is not gated. None loosened:

| case | what it covers | residual | worst 100 ms | tolerance |
|------|----------------|---------:|-------------:|----------:|
| amp_veltrack | `amp_veltrack` 0, 50, -100, -50, an explicit 100 and the plain default, at velocities 20, 64 and 127 | -68.0 dB | -64.1 dB | -60 dB |
| amp_velcurve | sparse `amp_velcurve_N` points (gaps filled linearly, ends defaulting to (0, 0) and (127, 1)), a single middle point, a flat curve with `amp_veltrack=50`, an inverted curve, a curve with `amp_veltrack=-100`, adjacent points 20/21; velocities 1, 20, 30, 45, 64, 90, 127 | -67.9 dB | -64.5 dB | -60 dB |
| amp_gain | `amplitude` 50/80/0/150, `group_volume`, `master_volume` (added to `volume`), `group_amplitude` and `master_amplitude` (multiplied into `amplitude`), `<master>`/`<group>` resets | -67.4 dB | -63.9 dB | -60 dB |
| ampeg_vel2 | `ampeg_vel2attack`, `vel2decay`, `vel2sustain` (negative), `vel2release`, each on its own looped region, and one region with all four plus `ampeg_dynamic=1`; velocities 25 and 127 | -64.5 dB | -58.5 dB | -60 dB |
| amp_keytrack | `amp_keytrack`/`amp_keycenter` around 60 and 84, a track with the default centre, +12 dB per key at the top | -68.1 dB | -59.7 dB | -60 dB |

`ampeg_vel2` has the lowest margin on the worst window (the file is short and the envelope tails differ by the oracle's block-wise ADSR). The
`ampeg_dynamic=1` region matches the engine, which ignores the flag: with `vel2*` alone the trigger velocity never changes, so sfizz's per-chunk
re-evaluation yields the same values.

`sample_null_neg_strip134_<case>` imports the same SFZ with its Story 13.4 opcodes removed (`amp_*`, `ampeg_vel2*`, `amplitude`, `*_amplitude`,
`*_volume`) and requires the null test to FAIL on residual: the velocity law, gains, key tracking and envelope times would all be the defaults.

## Story 13.5: CC at voice start and sfizz pseudo-CCs

One fixture instrument per family, generated by `python3 generate_suite.py story135` (only these cases are written), goldens rendered by the sfizz 1.2.3 oracle with
`regenerate_goldens.sh cc_gates cc_modulation cc_envelope cc_pseudo`. Every controller is moved **before** the note it is meant for and, for a target sfizz follows
continuously, only while no voice that reads it sounds (the previous voice, release tail included, has died when the controller moves): sfizz modulates amplitude, volume, pan
and tune every block, the engine reads the controller when the note starts. Residuals measured on macOS arm64 (Apple clang 21); the -60 dB tolerance applies to the overall residual only.

| case | what it covers | residual | worst 100 ms | tolerance |
|------|----------------|---------:|-------------:|----------:|
| cc_gates | `locc`/`hicc` split of two layers at CC20 63\|64 and a 30..100 gate, the fill-gap (`hicc=100` passes 100, not 101), `lohdcc`/`hihdcc` (CC 31 fails, 32 passes, 95 passes, 96 fails), `set_cc21=80` as the initial value, `hicc23=10` with the controller at its default 0, CC changes between notes | -67.9 dB | -63.2 dB | -60 dB |
| cc_modulation | `amplitude_oncc` (default curve, a `<curve>` block, a predefined curve), `volume_oncc`, `gain_cc` (SFZ 1 spelling), `pan_oncc` on a mono and a stereo sample, `tune_oncc`/`tune_cc` (positive and negative), `offset_oncc`, `*_curvecc` | -67.6 dB | -59.2 dB | -60 dB |
| cc_envelope | `ampeg_release_oncc`, `ampeg_attackcc` (SFZ 1 spelling), `ampeg_decay_oncc` with `ampeg_sustain_oncc`, `ampeg_delay_oncc` with `ampeg_hold_oncc`, `ampeg_start_oncc`, `ampeg_release_curvecc`, `ampeg_sustain_curvecc`, each at controller values 0, 64, 127 on a looped sample | -65.3 dB | -61.0 dB | -60 dB |
| cc_pseudo | pseudo-CCs 131 (velocity, on amplitude, volume and the attack), 137 (alternate, on pan and amplitude with a curve), 140 and 141 (key delta, on volume, tune and the release; raw on the matrix targets, curved on the envelope), over 40 notes with key jumps up and down | -69.4 dB | -62.5 dB | -60 dB |

The random pseudo-CCs 135 and 136 are not in a null fixture: sfizz draws from a fixed-seed generator the engine cannot share (the same reason `lorand`/`hirand` layers are not
null-picked in the corpus), so they are covered by the unit tests (`test_pseudo_ccs`: deterministic for a seed, in range). `sample_null_neg_strip135_<case>` imports the same SFZ with its
Story 13.5 opcodes removed (`locc`/`hicc`/`lohdcc`/`hihdcc`, `set_cc`, every `*_oncc`, `*_cc`, `*_curvecc` and `ampeg_*cc`) and requires the null test to FAIL on residual (+2.9,
+0.6, -11.1 and -0.6 dB): the gated layers would all sound, and the controller-driven gains, pans, pitches, offsets and envelope times would be the defaults.

**Known limit, shown by the first version of `cc_modulation`.** With the notes 150 ms apart the controller of the next note moved 10 ms after the previous key up, inside its release
tail: sfizz followed the new value, the engine kept the old one, and the case nulled at -37.5 dB (the error sits entirely in the release windows, the notes themselves null at
-65 dB). The shipped fixture spaces the notes so that no voice sounds when a controller moves; a library that maps a moving controller (a pedal, a wheel) to a continuously
modulated target will differ from sfizz in the same way.

## Story 13.6: choke groups and polyphony limits

Generated by `python3 generate_suite.py story136` (only these cases are written), goldens rendered by the sfizz 1.2.3 oracle with
`regenerate_goldens.sh choke_groups choke_sustain polyphony_limits`. The voices are looped samples, so a missing or late cut shows as sustained energy in the residual.
Residuals measured on macOS arm64 (Apple clang 21); the -60 dB tolerance applies to the overall residual only.

| case | what it covers | residual | worst 100 ms | tolerance |
|------|----------------|---------:|-------------:|----------:|
| choke_groups | open hats 60 (`off_mode` default: fast), 61 (`off_mode=normal`, own 0.12 s release), 63 (`off_time=0.08`) cut by the closed hat 65 (`group=2`); `group=3 off_by=3` on keys 67 and 69 (another note cuts, a retrigger of the same note does not); a cut of a note that already got its note off and is releasing | -62.5 dB | -53.5 dB | -60 dB |
| choke_sustain | the sustain pedal (CC64) is down: an open hat and a plain note are released and held by the pedal, the closed hat cuts the open hat at once, the plain note rings until the pedal comes up | -62.6 dB | -60.2 dB | -60 dB |
| polyphony_limits | `<group> group=5 polyphony=2` over three regions (the third note cuts the oldest, the fourth the next); `note_polyphony=1` (equal or louder retrigger cuts, a quieter one does not), `note_polyphony=1 note_selfmask=off` (the oldest goes whatever the velocity), `note_polyphony=2` (the quietest of the older voices goes); `polyphony=1` on a three-key region | -64.4 dB | -58.8 dB | -60 dB |

`sample_null_neg_strip136_<case>` imports the same SFZ with its Story 13.6 opcodes removed (`group`, `off_by`, `off_mode`, `off_time`, `polyphony`, `note_polyphony`, `note_selfmask`) and
requires the null test to FAIL on residual (-0.8, -7.4 and -2.8 dB): without the cuts every voice would ring on until its note off.

**What the null test shows about sfizz's stealing and `off_mode` timing.** Nothing diverges at the 64-frame block size of the oracle: the cut starts at the note on of the cutting voice in both
renderers, the 6 ms (fast), `ampeg_release` (normal) and `off_time` (time) tails agree, the oldest voice of a group and the quietest masked voice of a note are the ones sfizz releases, and its sister
voices go with them. The fixture timings avoid one trap that is not a divergence: two voices of one looped sample started a whole number of half periods apart cancel each other (the first
version of `choke_groups` retriggered note 69 exactly 12000 frames = 82.5 periods after the first, so the two voices nulled each other in BOTH renderers, which says nothing about whether the first voice was spared).
Not covered by a fixture: the trigger=release regions that sfizz fires for a choked voice (the engine does not, see `engine/core/README.md`), and `note_polyphony` ties between equal velocities.


## Real libraries

`../sample_demo_null_test.cpp` (ctest `sample_demo_null_test`) imports every `*.sfz` below `VELORA_SFZ_DEMO_DIR` (Salamander Grand Piano,
a VSCO2 instrument; at most `VELORA_DEMO_MAX_SFZ`, default 4), renders `midi/demo_probe.mid` through the oracle and the engine and null-tests
them at `VELORA_DEMO_TOLERANCE_DB` (default -60). It skips (exit 77) without the directory or without a built oracle. It was exercised
mechanically on this synthetic library; it has not been run on the real libraries, which are not in the repository.
A library using opcodes outside the Story 5.1 subset fails at import with the offending file:line.

Story 5.2 renders every library twice: `midi/demo_probe.mid` (notes over the keyboard) and `midi/demo_features.mid` (every key from C0 to B2 pressed
briefly as a possible keyswitch, each followed by two notes; then a chord held for 6.6 s while CC1 and CC2 sweep up and down in whole steps). This
is the **real-library suite entry for a Karoryfer instrument**: the story names one, it is not available on the machine that built this story
(libraries are never committed), so the entry skips (exit 77) without `VELORA_SFZ_DEMO_DIR`; point the variable at a directory that holds the
instrument and `ctest -R sample_demo_null` runs both probes (`VELORA_DEMO_MAX_SFZ` raises the default 4 files). A Karoryfer instrument that uses
opcodes outside the subset (LFOs, `*_oncc` modulation, ...) fails at import until the Story 5.4 corpus work. The probe was exercised mechanically
on this directory's 17 synthetic instruments (`VELORA_SFZ_DEMO_DIR=tests/sample_suite/sfz VELORA_DEMO_MAX_SFZ=30`): 32 of the 34 renders are
-61.2 .. -68.2 dB; the two exceptions are `filters.sfz` with the notes probe (-39.9 dB: only two quiet filtered notes sound, rms -56 dBFS in a mostly
silent file, so the oracle's 16-bit floor of about -89 dBFS is the residual) and `filters.sfz` with the features probe (-58.4 dB, the same floor
against a quieter file than the dedicated case); neither is an engine difference (the `filters` case, with louder notes, is -64.3 dB).
