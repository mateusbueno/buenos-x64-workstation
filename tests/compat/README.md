# Compatibility corpus (Story 8.5, FR49, AR29, NFR44)

Every persisted file a release has ever written, kept so every later build proves it still opens it. Readers accept version N and N-1 (older and unknown
major are typed errors), so a file written by release R must open on R+1 (as its N-1) and the corpus checks it on the current build.

| Dir | What | Opened by |
|-----|------|-----------|
| `live_sets/` | Live Sets (`*.liveset`): minimal, 8 parts with scenes and ASSIGN, FM/VA, missing library, Pro 16 parts, newer schema with unknown fields | `compat_corpus_test` (engine/host) |
| `setlists/` | setlist libraries (`*.library`) and default ASSIGN maps (`*.pb`) | `compat_corpus_test` |
| `config/` | sysd config files (`*.json`) | `compat_config_test` (ui) |
| `releases/<tag>/<kind>/` | files added by a release job | both |

`live_sets/` and `setlists/` are regenerated from the fixtures by `cmake --build build --target live_set_corpus_regen` and `setlist_corpus_regen`, and their
goldens live in `engine/host/tests/golden/`; regenerate only when a change is intended. `live_sets/` and `setlists/` are generated seed files: they are regenerated by those targets (review the diff; the drift tests fail if they change unintentionally). Released files under `releases/` are immutable: never edited or deleted, a format change adds files.

## Gate

`ctest --test-dir build -R compat` walks this tree recursively. A file that does not open, or that no reader claims (unknown extension), prints
`COMPAT FAIL: ... <path>` and fails the run. `ctest -R compat_gate_selftest` proves the gate is not vacuous (a planted broken file must fail it).

## A release adds its files

From the release job, with the release's writers' output (a Live Set, a setlist library, the default ASSIGN map, the sysd config):

    tools/compat/add_release.py v1.2.0 out/a.liveset out/setlists.library out/assign_default.pb out/sysd_config.json \
        --gate build/engine/host/compat_corpus_test --gate-config build/ui/compat_config_test

The candidates are first checked by the gates on a temp copy; only if they pass are they installed in `releases/v1.2.0/<kind>/` (never overwritten with different bytes), to be committed with the release.
